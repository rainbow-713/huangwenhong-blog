# Git 提交规范（Commit Convention）

## 提交信息格式
```
<类型>: <简短描述>
```
描述用中文，不超过 50 字，说清"改了什么、为什么"。

## 类型定义
| 类型 | 使用场景 | 示例 |
|------|----------|------|
| `feat` | 新功能、新页面 | `feat: 新增面试准备题库页` |
| `fix` | 修复问题 | `fix: 修复移动端导航菜单无法收起的问题` |
| `docs` | 文档变更（含笔记内容、面试复盘） | `docs: 新增 Vue3 响应式原理学习笔记` |
| `style` | 样式调整（不影响逻辑） | `style: 优化首页简介卡片配色` |
| `refactor` | 重构（不增功能不修问题） | `refactor: 抽离卡片组件为通用组件` |
| `chore` | 构建、配置、依赖等杂项 | `chore: 新增 Vercel 路由重写配置` |

## 提交习惯要求
1. 一次提交只做一件事，禁止把多个不相关的改动混在一次提交里
2. 项目初始化、每个页面完成、每次部署配置都要单独提交，保持提交历史清晰——面试时提交历史本身就是展示品
3. 禁止提交 `node_modules/`、`dist/` 等目录（已在 .gitignore 中排除）

## 分支约定
- `master` 为主分支，保持随时可部署状态
- 每次部署上线前执行 `npm run build` 确认构建通过
