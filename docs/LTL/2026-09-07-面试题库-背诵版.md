## 一、HTML / CSS

### 题库 1 · 说说你对盒模型的理解，box-sizing 有什么作用？
**要点**：盒模型 = content + padding + border + margin ｜ 默认 content-box：width 只算内容，加 padding 会撑大 ｜ border-box：width 含 padding+border，好算 ｜ 项目里全局 reset 设了 border-box
**参考答案**：盒模型描述元素占空间的组成：内容、内边距、边框、外边距。默认是 content-box，设的 width 只是内容宽度，加了 padding 元素会变大、布局难算。所以实际项目会全局设 `box-sizing: border-box`，让 width 直接等于元素最终宽度。我的博客全局样式里就是这么做的。

### 题库 2 · Flex 布局常用属性？怎么垂直水平居中？
**要点**：容器 `display:flex`；`justify-content` 主轴、`align-items` 交叉轴 ｜ `flex:1` 填充剩余空间 ｜ 居中＝两个都 center ｜ `flex-direction` 改主轴方向
**参考答案**：Flex 是一维布局。容器上 `display:flex` 开启，`justify-content` 管主轴、`align-items` 管交叉轴，垂直水平居中就是两个都设 center。我的博客整站就是 flex 纵向排列：导航、内容区、页脚，内容区 `flex:1` 撑开剩余高度保证页脚贴底。

### 题库 3 · 如何实现移动端适配？
**要点**：viewport meta 标签 ｜ `@media` 媒体查询按断点调样式 ｜ 相对单位/百分比 ｜ 移动优先
**参考答案**：先用 viewport meta 让页面按设备宽度渲染，再用媒体查询在不同断点调整布局，比如 768px 以下把多列变单列、缩小字号。我的博客就是用 768px 一个断点做响应式，导航在移动端也会简化成汉堡菜单。

## 二、JavaScript

### 题库 4 · var、let、const 的区别？
**要点**：var 函数作用域、有变量提升、可重复声明 ｜ let/const 块级作用域、无提升 ｜ const 不能重新赋值（对象属性仍可改）｜ 规范：默认 const，需改才 let，禁用 var
**参考答案**：var 是函数作用域且有变量提升，容易意外覆盖；let、const 是块级作用域。const 表示绑定不可变，但如果是对象，内部属性仍可改。开发规范是优先 const、需要变更才用 let、不用 var。

### 题库 5 · 箭头函数和普通函数有什么区别？
**要点**：箭头函数没有自己的 this，继承定义时作用域的 this ｜ 不能 new ｜ 没有 arguments ｜ 适合回调，不适合对象方法
**参考答案**：最大区别是 this 指向：普通函数的 this 看调用方式，箭头函数没有自己的 this，直接继承外层作用域的。所以箭头函数适合做回调、不怕 this 丢失，但不能用来 new 对象。

### 题库 6 · 说说你对 Promise 的理解？
**要点**：解决回调地狱，表示异步最终结果 ｜ 三态 pending/fulfilled/rejected 且不可逆 ｜ then 链式，每个 then 返回新 Promise ｜ Promise.all、async/await 是语法糖
**参考答案**：Promise 是表示异步操作最终结果的对象，有 pending、fulfilled、rejected 三种状态，状态一旦确定就不能再变。它支持 then 链式调用，把嵌套回调变成链式写法。async/await 本质是 Promise 的语法糖，让异步代码看起来像同步。

### 题库 7 · 深拷贝和浅拷贝的区别？
**要点**：浅拷贝只复制第一层，嵌套仍共享引用 ｜ 深拷贝递归复制所有层 ｜ 浅拷贝：Object.assign、展开符 ｜ 深拷贝：JSON（有局限）或手写递归
**参考答案**：浅拷贝只复制对象第一层，嵌套对象还是同一个引用，改一边另一边也变；深拷贝是完整复制一份独立数据。展开运算符是浅拷贝，`JSON.parse(JSON.stringify())` 能做深拷贝但处理不了函数、undefined、循环引用，所以有时要手写递归。

### 题库 8 · == 和 === 的区别？
**要点**：`==` 比较前做隐式类型转换 ｜ `===` 类型和值都要相等、不转换 ｜ 例：`0 == ""` 为 true，`0 === ""` 为 false ｜ 规范：一律用 ===
**参考答案**：`==` 会先做类型转换再比较，比如 `0 == ""` 是 true，容易出隐藏 bug；`===` 是严格相等，类型不同直接 false。开发规范是一律用 `===`，需要转换时自己显式转。

### 题库 9 · 什么是闭包？有什么用？
**要点**：函数 + 它能访问的外部变量 ｜ 典型：外层返回内层，内层用了外层变量 ｜ 用途：私有变量、防抖节流的 timer、计数器 ｜ 注意内存占用
**参考答案**：闭包就是函数能记住并访问它定义时所在作用域的变量，哪怕它在外面被调用。典型写法是外层函数返回一个内层函数，内层用了外层的变量。用途很多，比如防抖函数里存的 timer 就是靠闭包保住的，每次调用都能访问同一个 timer。

## 三、Vue

### 题库 10 · Vue3 的响应式原理？和 Vue2 有什么区别？
**要点**：Vue3 用 Proxy 代理整个对象，Vue2 用 defineProperty 逐属性劫持 ｜ Proxy 能拦截新增/删除/数组下标，性能更好 ｜ 依赖收集 + 触发更新
**参考答案**：Vue3 用 Proxy 劫持数据：渲染时访问了哪些数据就收集为依赖，数据变化时通知依赖更新。相比 Vue2 的 defineProperty，Proxy 直接代理整个对象，能检测属性新增删除和数组下标变化，也不用递归初始化所有属性。我在博客里专门写过一篇笔记总结这个原理。

### 题库 11 · ref 和 reactive 的区别？怎么选？
**要点**：ref 包任意类型、访问要 .value；reactive 只代理对象 ｜ 解构 reactive 会丢响应式 ｜ 模板中 ref 自动解包 ｜ 组件内保持统一
**参考答案**：ref 可以包基本类型和对象，JS 中用 `.value` 访问，模板里自动解包；reactive 只能用于对象，直接解构会丢失响应式。我的习惯是基本类型用 ref、复杂对象用 reactive，一个组件内保持风格统一。

### 题库 12 · 组件之间怎么通信？
**要点**：父传子 props、子传父 emit ｜ 跨层级 provide/inject ｜ 全局状态 Pinia/Vuex ｜ 兄弟通过共同父组件中转
**参考答案**：最常用的是 props 向下传数据、emit 向上发事件。跨多层组件用 provide/inject 避免层层透传，复杂的全局共享状态才引入 Pinia。我的博客是纯展示项目，主要用 props 传数据，比如笔记卡片就是父组件把每条笔记通过 props 传进去。

### 题库 13 · v-if 和 v-show 的区别？
**要点**：v-if 真销毁/重建，v-show 只切 display ｜ v-if 切换开销大但初始不渲染，v-show 初始就渲染 ｜ 频繁切换用 v-show，条件很少成立用 v-if
**参考答案**：v-if 条件为假时元素根本不渲染，切换时销毁重建；v-show 一直渲染，只是用 display 控制显隐。所以频繁切换用 v-show 性能更好，几乎不出现的分支用 v-if 省初始渲染。

## 四、工程化与网络

### 题库 14 · 从输入 URL 到页面显示发生了什么？
**要点**：DNS 解析 → TCP 连接 → 发 HTTP 请求 → 服务器响应 ｜ 解析 HTML 建 DOM、CSS 建 CSSOM、合成渲染树 ｜ 布局 Layout → 绘制 Paint ｜ 加分：缓存、SPA 与多页区别
**参考答案**：先 DNS 解析域名拿到 IP，建立 TCP 连接后发 HTTP 请求，服务器返回 HTML。浏览器解析 HTML 建 DOM 树、CSS 建样式树，合成渲染树后布局和绘制上屏。遇到 JS 会阻塞解析，所以脚本一般放 body 底部或加 defer。我的博客用 Vite 打包后资源按需加载，也是围绕这个流程做优化。

### 题库 15 · Vite 为什么启动快？和 Webpack 的区别？
**要点**：开发时不打包，基于浏览器原生 ES Module 按需编译 ｜ 冷启动只处理入口，访问到才编译 ｜ 生产用 Rollup 打包 ｜ Webpack 是先整体打包再启动
**参考答案**：Vite 开发时利用浏览器原生 ES Module，不做整体打包，启动几乎是瞬间的，访问哪个模块才即时编译哪个。传统 Webpack 启动前要先把整个项目打包一遍，项目越大越慢。生产构建时 Vite 用 Rollup 输出优化后的产物。

> ⚠️ 部署只说 **GitHub Pages**（Vercel 已经在 Day 2 亲手删掉了，别再提"部署了两个平台"）——面试官翻你代码，只会看到 GitHub Pages 的自动部署。

### 题库 16 · 介绍一下你的个人博客项目？
**要点**：定位＝求职作品集，在线简历 + 学习记录，已上线 ｜ 页面：首页、关于我、学习笔记、项目展示 ｜ 常规 Vue3 + Vite，纯静态无后端，内容写本地 JS ｜ 亮点在部署：GitHub Actions 自动部署到 GitHub Pages
**参考答案**：这是我做的求职作品集网站，相当于在线简历加学习记录，有首页、关于我、学习笔记、项目展示几个页面。技术上是很常规的 Vue3 + Vite，页面切换用路由，内容写在本地 JS 文件里，纯静态不需要后端。它已经上线了，用 GitHub Pages 部署的，中间解决过刷新 404 和国内访问 GitHub 慢这些实际问题。

### 题库 17 · 你的博客是怎么部署上线的？
**要点**：Gitee + GitHub 双平台托管 ｜ GitHub Actions：push 到 main 自动打包发布到 Pages ｜ 踩坑：国内访问 GitHub 慢用 hosts 加速、刷新 404
**参考答案**：代码托管在 Gitee 和 GitHub 上。GitHub 那边配了自动部署：推代码到 main 分支，GitHub Actions 就自动打包发布到 Pages，全程不用手动操作。中间主要踩了两个坑：一个是国内访问 GitHub 很慢，配了 hosts 加速解决；另一个是单页应用刷新会 404。

### 题库 18 · 单页应用刷新 404 是怎么回事？怎么解决？
**要点**：SPA 只有一个 index.html，深层路径只是前端路由管理 ｜ 刷新时浏览器真去服务器找文件，找不到就 404 ｜ GitHub Pages 不支持重写，用自定义 404 页记住原地址→跳回首页→再还给前端路由
**参考答案**：单页应用其实只有一个 index.html，像 `/notes/1` 这种地址只是前端在管理。直接刷新时浏览器会去服务器找这个文件，找不到就 404。解决思路是让服务器把请求都指回 index.html。我用的是 GitHub Pages，它不支持重写规则，所以我用了社区通用办法——自定义一个 404 页面（public/404.html），先记住原地址，跳回首页再还原给前端路由。

### 题库 19 · 博客的数据存在哪里？为什么不用后端？
**要点**：数据写在本地 JS 文件，数组导出、组件 import ｜ 更新：往数组加一条重新部署 ｜ 纯展示、无用户交互和动态数据，静态站最合适 ｜ 好处：免费托管、加载快、免维护服务器
**参考答案**：写在项目里的 JS 文件中，一个数组导出、组件 import 进来用。加一篇笔记就往数组里加一条，重新部署就更新了。不用后端是因为内容就是我自己写的笔记和介绍，没有用户交互和动态数据，纯静态最合适——免费托管、加载快、不用维护服务器。
