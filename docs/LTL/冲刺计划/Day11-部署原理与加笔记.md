## ① 先读懂（上午 · 约 2h）——大白话

### 1. SPA 刷新为什么会 404
你的博客是**单页应用（SPA）**，服务器上其实**只有一个 `index.html`**。像 `/notes/1` 这种网址是**前端路由**在浏览器里"假装"出来的——正常点进去没事，因为压根没找服务器要新页面。

但**一旦你按刷新**：浏览器会真的跑去服务器找 `/notes/1` 这个文件——服务器上根本没这个文件，就报 **404**。
```
点链接进 /notes/1  → 前端路由在浏览器里切换，不找服务器 → ✅ 正常
直接刷新 /notes/1   → 浏览器真的向服务器要 /notes/1 文件 → ❌ 服务器没有 → 404
```

### 2. 怎么解决：让所有请求都回到 index.html
核心思路：**让服务器把找不到的路径都指回 `index.html`，再交给前端路由处理**。
- 一般平台（如 Vercel）可以配"重写规则"直接把所有路径 rewrite 到 index.html。
- 但 **GitHub Pages 不支持自定义重写规则**，所以我们用一个取巧办法——**自定义 404 页兜底**：
```
用户刷新 /notes/1 → GitHub Pages 找不到 → 返回我们放的 public/404.html
   → 404.html 里一段脚本：把用户原本想去的地址(/notes/1)记下来
   → 跳回首页 index.html，并把地址通过 query 带回去
   → 首页脚本再把地址还给前端路由 → /notes/1 正确显示出来
```
- 打开 `public/404.html` 看一眼那段脚本就行，**能白板画出这个流程、讲清楚**，面试很加分。

### 3. `npm ci` vs `npm install`（部署流水线里为什么用 ci）
- `npm ci`：**严格**按 `package-lock.json` 装依赖，每次结果**一模一样**（可复现），所以自动化流水线（CI，就是 GitHub Actions）里用它。
- `npm install`：可能会**微调** lock 文件（比如版本有更新范围时），装出来的结果不保证每次完全一致。
- 一句话：**CI 里用 `ci` 图个"每次都装出一模一样的依赖"，避免"我这能跑、线上跑不了"。**

### 4. hosts 加速（了解即可）
GitHub 有时连得慢，可以手动把它的域名指到一个较快的 IP（改本机 `hosts` 文件），绕过慢的 DNS 解析。知道有这回事即可。
