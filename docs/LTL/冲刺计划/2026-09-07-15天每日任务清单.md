## Day 2 · 网站的"皮肤"（CSS + 盒模型）＋第一次动手改项目

**今天目标**：搞懂 CSS 和盒模型，自己敲一遍全局样式 `global.css`；再亲手把没用的"海外备用部署 Vercel"从项目里删掉——这是你第一次真正改动这个项目。
**今天大概 5 小时**：上午读懂 CSS + 手敲 global.css（约 2.5h）→ 下午动手删 Vercel + 验证（约 1.5h）→ 傍晚手写题 + 背题 + 复盘（约 1h）。

**① 先读懂（上午）**——用大白话把这几个词搞懂，读懂一个再往下看：
- **CSS**：管网页"长什么样"——颜色、大小、位置、间距。就是预备篇说的"装修"。
- **选择器**：告诉浏览器"给谁化妆"。比如 `.card` 就是"所有挂了 card 牌子的元素"。
- **CSS 变量**：一个颜色只定义一次、起个名（比如 `--color-primary`），后面到处用 `var(--color-primary)`。好处是**想换主题色，改一个地方，整个网站都跟着变**。
- **盒模型（重点，面试必问）**：网页上每个元素都是一个"盒子"，从里到外四层——`content` 内容（盒子里装的东西）→ `padding` 内边距（内容和边框之间的空隙）→ `border` 边框 → `margin` 外边距（这个盒子和别的盒子之间的距离）。
- **`box-sizing: border-box`**：让"你设的宽度"把 padding、border 也算进去，排版更好控制。global.css 里就有这句。

**② 动手做**

**A｜上午后半：手敲全局样式 global.css（练 CSS）**
1. 打开 `src/styles/global.css`，对照上面的讲解一段段看懂：`:root` 是定义变量、`*` 是重置浏览器默认样式、`.container`/`.card`/`.tag` 是通用样式。

一步步来，别跳：
1. **改之前先确认它是好的**：终端敲 `npm run dev`，浏览器打开博客，确认一切正常。（这样万一改完出问题，你就知道是刚才动的地方）

## Day 3 · 乐高积木：组件 + Flex 布局

**今天目标**：搞懂"组件"和 Flex 布局，手敲出笔记卡片 `NoteCard.vue`，并练会"用 Flex 把东西放到正中间"（面试超高频）。
**今天大概 5 小时**：上午读懂组件 + Flex（约 2h）→ 下午手敲 NoteCard + Flex 居中专项练（约 2h）→ 傍晚手写题 + 背题 + 复盘（约 1h）。

**① 先读懂（上午）**——大白话：
- **组件**：可复用的"乐高积木"。`NoteCard.vue` 就是一张"笔记卡片"积木，哪里要显示笔记，就把这块积木搬过去用。

## Day 4 · JavaScript 基础 + 首页

**今天目标**：搞懂 JS 最基础的变量、箭头函数、computed，手敲首页 `HomeView.vue` 的结构。
**今天大概 5.5 小时（概念多，慢慢来）**：上午啃 JS 基础概念（约 2.5h）→ 下午手敲首页（约 2h）→ 傍晚手写题 + 背题 + 复盘（约 1h）。

**① 先读懂（上午，今天是重点，慢慢看）**——大白话：
- **变量**：给数据起个名字，像贴了标签的盒子。`let count = 0` 就是拿个盒子叫 count，里面装着 0。
- **let / const / var**：`const`＝常量，赋值后不能再改（能用就优先用它）；`let`＝可以改；`var`＝老写法、有坑，别用。
- **箭头函数**：写函数的一种简写。`function add(a,b){return a+b}` 可以简写成 `const add=(a,b)=>a+b`；它有个特点：没有自己的 this（这句先记住，面试可能问）。
- **插值 `{{ }}`**：把数据显示到页面上，比如 `{{ profile.name }}` 就是把名字显示出来。
- **computed（计算属性）**：根据别的数据"算"出一个新数据，而且有缓存——依赖的数据没变，它就不重新算（比每次手动算更省）。

**② 动手做（下午）**
1. 打开 `src/views/HomeView.vue`。
2. 看懂模板：`{{ profile.name }}` 显示名字、`v-for="skill in profile.skills"` 把技能循环成一个个标签。
3. 看懂 `<script setup>` 里的 `const latestNotes = computed(() => notes.slice(0, 3))`——从所有笔记里取最新 3 篇显示在首页。
4. **关掉**，凭记忆重敲 HomeView 的模板部分 + 那段 computed。

**③ 手写题：深拷贝（傍晚）**（《面试包》第五节第 4 题）
- 大白话：浅拷贝只复制最外面一层、里面几层还和原来共用（改一个另一个也变）；深拷贝是里里外外全复制一份独立的。
- 三步练：先记住快方法 `JSON.parse(JSON.stringify(obj))`，再重点练**手写递归版**（能讲清递归版就赢过大部分实习生）→ 白纸默写递归版。

**④ 要背的题**：**题库 4（var/let/const）+ 题库 5（箭头函数）**。

## Day 5 · 数据驱动视图 + 笔记列表

**今天目标**：亲眼见一次"改数据、页面自动变"（Vue 最核心的思想），手敲笔记列表页 `NotesView.vue`。
**今天大概 5 小时**：上午读懂数据驱动 + `===`（约 2h）→ 下午手敲列表页 + 做实验（约 2h）→ 傍晚手写题 + 背题 + 复盘（约 1h）。

**① 先读懂（上午）**——大白话：
- **数据驱动视图**：Vue 最核心的思想。你不用手动去改页面上的字，你只要改数据，页面自己就跟着变（这叫"响应式"）。今天一定要亲眼见一次。
- **`==` vs `===`（面试必问）**：`===` 要求"类型和值都一样"（`1 === '1'` 是 false，因为一个是数字一个是字符串）；`==` 会偷偷帮你转类型再比（`1 == '1'` 是 true）。**永远优先用 `===`**，更安全。
- **数组结构**：`notes.js` 里每一篇笔记是一个对象，有 id / title / date / tags / summary 几个字段。

**② 动手做（下午）**
1. 打开 `src/views/NotesView.vue`（很短），看懂它把 notes 数组循环成一堆 NoteCard 卡片。
2. 打开 `src/data/notes.js`，看每篇笔记的结构（id/title/date/tags/summary）。

## Day 11 · 部署原理 + 改代码①（加一篇笔记）

**今天目标**：能给别人讲清"网站是怎么上线的、刷新为什么会 404、怎么解决"，并**真的动手改一次代码**（加一篇学习笔记）。
**今天大概 5 小时**：上午读懂部署 + 404 原理（约 2h）→ 下午动手加笔记（约 1.5h）→ 傍晚补手写错题 + 背题 + 复盘（约 1.5h）。

**① 先读懂（上午）**——大白话：
- **SPA 刷新为什么 404**：你的博客是"单页应用"，服务器上其实只有一个 `index.html`。像 `/notes/1` 这种网址是**前端路由**在浏览器里"假装"出来的。你正常点进去没事；但一旦按刷新，浏览器会真的跑去服务器找 `/notes/1` 这个文件——服务器上根本没这个文件，就报 404。
- **怎么解决**：核心思路是"让服务器把所有请求都指回 `index.html`，再交给前端路由处理"。GitHub Pages 不支持配置重写规则，所以我们用一个取巧的办法——自定义 404 页兜底：`public/404.html` 会先把用户原本想去的地址记下来，跳回首页，再把地址还给前端路由，于是页面又正确显示了。（这个能白板画出来、讲清楚，面试很加分。）
- **`npm ci` vs `npm install`**：`ci` 严格按 `package-lock.json` 装依赖，每次结果都一模一样（可复现），所以自动化流水线（CI）里用它；`install` 可能会微调 lock 文件。
- **hosts 加速**：GitHub 有时连得慢，可以手动把它的域名指到一个较快的 IP（改本机 hosts 文件），绕过慢的 DNS 解析。

**② 动手做（下午·改代码①：加一篇学习笔记）**
