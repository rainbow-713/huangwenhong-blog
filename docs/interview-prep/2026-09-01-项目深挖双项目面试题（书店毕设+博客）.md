## 第一轮：项目介绍与技术选型（热身 + 考察表达）

### Q1 请用 3 分钟介绍你的毕业设计「网上书店系统」
- **考察意图**：项目表达能力、是否真正自己做的、能否抓住重点
- **追问链**：
  1. 为什么选 Vue3 而不是 Vue2？为什么加 TypeScript？实际开发中 TS 帮你拦过什么错？
  2. 为什么没用 Element Plus / Ant Design 这类组件库？
  3. 这个项目和你的博客项目，技术栈几乎一样，你觉得能力上差在哪？
- **参考要点**：一句话定位 → 功能模块（商城/专栏/留言板/个人中心）→ 技术亮点（TS 类型、Pinia 状态、mock API 分层、路由守卫鉴权）→ 难点与收获

### Q2 两个项目都用了 Vue3 + Vite，说说你理解的"组件化开发"，书店项目里怎么划分组件的？
- **考察意图**：工程组织意识
- **追问链**：
  1. `BookCard` 和 `views/profile/CartPanel` 为什么放在不同目录？
  2. 组件之间怎么通信？`BookCard` 点"加入购物车"，数据是怎么流到购物车页面的？
- **参考要点**：通用组件放 `components/`、页面级组件放 `views/`；跨页面共享状态靠 Pinia 而不是层层 props

## 第二轮：书店项目核心机制（深挖，重点轮）

### Q3 你的登录是怎么实现的？路由守卫里怎么做的鉴权？
- **考察意图**：认证流程 + 对 localStorage 方案的认知边界
- **代码锚点**：`router/index.ts` 的 `beforeEach` 读 `localStorage.getItem('bookstore_user')`；`stores/user.ts` 的 `login/register`
- **追问链**：
  1. 把整个用户对象（含收藏列表）存 localStorage，有什么问题？
  2. `bookstore_users` 里密码是明文存的，真实项目里密码应该怎么存？（加盐哈希、绝不明文）
  3. 如果换成真实后端，前端登录态你会怎么设计？（JWT/Token + sessionStorage、axios 拦截器带 Authorization 头、401 统一跳登录）
  4. 你的守卫只判断"有没有登录"，如果有人篡改 localStorage 里的用户数据怎么办？
- **参考要点**：能主动说出"这是纯前端演示方案，真实项目必须后端校验"是加分项；能说出 XSS 可以读到 localStorage 是亮点

### Q4 为什么用 Pinia？setup 语法和 options 语法你选了哪个，为什么？
- **考察意图**：状态管理选型理解
- **代码锚点**：`stores/user.ts`、`stores/cart.ts` 均为 `defineStore('xx', () => {...})`
- **追问链**：
  1. Pinia 相比 Vuex 去掉了什么？（mutations）为什么能去掉？
  2. 你的购物车状态为什么放 Pinia 而不是放组件里？不放 Pinia 会怎样？
  3. `toggleFavorite` 里为什么要同时更新 `current` 和 `users` 表？如果只改一处会出什么 bug？
- **参考要点**：多组件共享 + 需要持久化 + 登录态全局可读；setup 语法对 TS 推导更友好

### Q5 你的数据层是怎么设计的？为什么把数据写成 `api` 目录下的异步函数？
- **考察意图**：分层架构意识、对"面向接口编程"的理解
- **代码锚点**：`src/api/index.ts` 用 `delay(200)` 模拟网络，数据来自 `data.ts`
- **追问链**：
  1. 既然数据是本地数组，为什么还要假装异步？（保持调用方式与真实接口一致，切换后端零改动）
  2. 如果下周接真实后端，你要改哪些文件？（只动 `api/` 层，视图不用动——说出这点是大加分）
  3. `package.json` 里装了 axios 和 json-server 但代码里没用，这是怎么规划的？
  4. 真实接口会失败，你的 API 层应该怎么处理错误？（try/catch、统一错误提示、loading 兜底）
- **参考要点**：视图层不关心数据来源；api 层是唯一的"数据出入口"

### Q6 购物车是怎么实现的？说说设计细节。
- **考察意图**：业务建模能力 + 细节功底
- **代码锚点**：`stores/cart.ts`
- **追问链**：
  1. `CartItem` 为什么存整个 `book` 对象而不是只存 `bookId`？两种方案各自的坑？
  2. 重复加同一本书怎么处理？`updateQty` 里 `Math.max(1, qty)` 是在防什么？
  3. `totalPrice` 用 `qty * price` 累加，JS 浮点数会有什么问题？（0.1+0.2=0.30000000000000004）真实电商怎么解决？（以"分"为单位存整数 / toFixed 展示 / decimal.js）
  4. 购物车数据存 localStorage，换浏览器/设备就丢了，真实项目怎么设计？（登录态下购物车跟账号走，后端存储）
  5. 你的项目有购物车但没有"下单"，如果补订单模块，前端要做什么？
- **参考要点**：能主动提到金额精度和未登录购物车合并问题，是面试官眼里的"做过真项目"信号

### Q7 图书搜索和筛选是怎么做的？
- **考察意图**：交互细节 + 性能意识
- **代码锚点**：`BookListView.vue` 的 300ms 防抖 watch、`displayBooks` computed 排序
- **追问链**：
  1. 为什么搜索要等 300ms？防抖和节流的区别？各自适用场景？
  2. 排序为什么放在前端 `computed` 里做，搜索却要重新请求 `bookApi.list`？这个设计一致吗？
  3. 如果书目从 12 本变成 10 万本，这套方案哪里会先崩？你会怎么改？（后端分页 + 搜索、虚拟列表、防抖请求带取消）
  4. 你的 `watch(keyword)` 和 `watch(activeCategory)` 会同时触发吗？有没有重复请求的隐患？
- **参考要点**：防抖 = 等你停手再执行；节流 = 固定频率执行

### Q8 项目里 TypeScript 用在了哪些地方？举几个例子。
- **考察意图**：TS 是真会还是只配了个环境
- **代码锚点**：`types/index.ts`、`Omit<Message, 'id'|'replies'|...>`、`Partial<User>`、`ref<Book[]>([])`
- **追问链**：
  1. `Omit` 是干什么的？你为什么在 `messageApi.create` 里用它？
  2. `updateProfile(patch: Partial<User>)` 为什么用 `Partial`？
  3. `current.value!.id` 这个感叹号是什么？什么时候必须用？有没有更安全的写法？
  4. `ref` 和 `reactive` 你用了哪个？为什么？
- **参考要点**：接口类型定义贯穿 store / api / 组件三层，改字段时编译期就能发现引用错误

## 第三轮：博客项目 + 部署工程化

### Q9 你的博客是怎么上线的？讲讲 GitHub Actions 那条流水线。
- **考察意图**：CI/CD 实操，这是简历亮点题
- **代码锚点**：`.github/workflows/deploy.yml`
- **追问链**：
  1. `npm ci` 和 `npm install` 的区别？为什么 CI 里用 `ci`？
  2. `concurrency` 配置是干嘛的？不加会怎样？
  3. 为什么要给 Vite 传 `BASE_PATH: /${{ github.event.repository.name }}/`？
  4. GitHub Pages 和 Vercel 你都部署了，为什么部署两套？各解决什么问题？
- **参考要点**：push 触发 → npm ci 精确安装 → 带子路径构建 → 上传 dist → 部署；子路径是为 Pages 项目站点 `/<仓库名>/` 服务

### Q10 SPA 部署到静态托管最大的坑是刷新 404，你两个项目分别怎么处理的？
- **考察意图**：对 history / hash 路由本质的理解
- **追问链**：
  1. 为什么 hash 路由不需要服务器配置？它的原理是什么？（# 后面的内容不会发给服务器）
  2. hash 路由有什么缺点？为什么博客不用它？
  3. Vercel 上你是怎么修的？（vercel.json rewrites 全部指向 index.html）
  4. GitHub Pages 不支持 rewrites，你怎么兜底的？（404 页面重定向技巧）
  5. `createWebHistory(import.meta.env.BASE_URL)` 里的 `BASE_URL` 不传会怎样？
- **参考要点**：这是两个项目路由 模式"一个 hash 一个 history"差异的根源，能把因果讲清楚就是高分

## 第四轮：安全、性能与开放设计题（压力面）

### Q11 你的文章详情用了 `v-html` 渲染 `article.content`，你知道这有什么风险吗？
- **考察意图**：XSS 安全意识
- **代码锚点**：`ArticleDetailView.vue` 的 `v-html="article.content"`
- **追问链**：
  1. 如果留言板内容也用 `v-html` 渲染，攻击者可以做什么？
  2. 怎么防御？（不渲染原始 HTML / DOMPurify 白名单过滤 / 后端过滤）
  3. Vue 的 `{{ }}` 插值为什么是安全的？
- **参考要点**：`{{ }}` 会转义为纯文本；`v-html` 只用于可信内容；你的文章数据是本地写死的所以安全，但要能说出边界

### Q12 如果书店要做性能优化，你会从哪几个方面入手？
- **考察意图**：优化方法论（不是背清单，要能结合项目）
- **追问链**：
  1. 你项目里已经做了哪些优化？（路由懒加载——每个页面独立 chunk）
  2. 图书封面图片 12 张直接全加载，怎么优化？（懒加载 `loading="lazy"`、压缩、WebP）
  3. 怎么知道打包后哪个依赖最大？（rollup-plugin-visualizer / vite-bundle-analyzer）
- **参考要点**：网络层（懒加载/图片/缓存）→ 渲染层（虚拟列表）→ 度量先行

### Q13 毕业设计做下来，你觉得最难的是什么？如果再做一遍，你会改什么？
- **考察意图**：复盘能力、成长性（开放题，没有标准答案，但不能答"没什么难的"）
- **参考要点**：结构 = 难点是什么 → 怎么解决的 → 现在回头看还有什么更好的做法
