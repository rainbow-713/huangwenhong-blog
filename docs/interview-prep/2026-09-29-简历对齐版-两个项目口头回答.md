## 一、开场必答：为什么博客写得比毕设还细？

面试官很可能问："你毕设是一整个书店应用，怎么只写两行，反而把一个简单博客写这么多？" 这是**送分题**，答好直接把"书店薄"反转成诚实加分：

> "毕设是在一个开源模板的基础上做的二次开发，功能能跑，但底层架构不全是自己从零搭的，所以我只列了自己动手做的模块。博客虽然功能简单，却是我跟着资料一步步自己搭起来、并且**独立走完部署上线全流程**的——代码托管、自动部署、还有国内访问 GitHub 慢的问题都是我自己解决的，每个地方我都能讲清楚，所以更想拿它当主要作品来展示。"

**为什么这样答安全**：不撒谎（毕设确实是二开）、把火力引向博客的部署经历（你真操作过、最有底气）、面试官会觉得你有自我认知、不吹。

## 二、云海书坊（书店毕设）—— 对应简历 2 条 bullet

### 书店 bullet 1：做了哪些功能

简历写的是"图书商城（搜索/分类/详情）、购物车、登录、留言板、个人中心"。被问"具体介绍下"时：

> "云海书坊，一个网上书店。主要几块功能：图书商城可以搜索、按分类筛选、看详情；有留言板；个人中心里有购物车和收藏。技术上就是现在比较主流的 Vue3 全家桶——Vue3 + TypeScript + Pinia + Vue Router。"

**只报功能和技术栈名，不主动展开原理**。他问哪块再答哪块（购物车→旧口径 Q6，登录→Q3，TS→Q8）。

### 书店 bullet 2：组件怎么划分

简历写的是"视图组件 + 公共组件分层、个人中心路由嵌套"。被问"结构怎么组织的"时：

> "通用的部分抽成公共组件，比如图书卡片、顶部导航、底部页脚，放在 components 目录；每个页面是独立的视图组件放 views 目录；个人中心里还有几个子页面，用的是路由嵌套。页面之间的共享状态走 Pinia，父子组件就是 props 传下去、事件传上来。"

### 如果书店被追到深层原理（TS 类型 / Pinia 响应式 / 防抖）

统一兜底一句，说完就停：

> "这部分是模板里本来就有的，我能看懂它的作用，但让我自己从零写还不熟，毕设里我主要精力在读懂结构再改功能上。"

**绝不主动提**：TypeScript 高级类型（Omit/Partial）、Pinia 源码、搜索防抖、订单模块、大数据量优化——提了就要接得住，接不住就穿帮。

## 三、个人博客（主项目）—— 对应简历每条 bullet

> 博客被问代码时的总口径是"**写法很常规，都是官方文档的写法**"。下面每条给一句能答的话，答完就停，别自己往架构设计上引。

### 博客 bullet 1：懒加载路由 + 全局守卫设标题

> "页面组件不是一次性全加载，路由里用箭头函数 `import()` 动态引入，访问到哪个页面才加载哪个，首屏更快。全局守卫是 `router.beforeEach`，每次切换页面前触发，我用它把每条路由里配的标题同步到浏览器标签上。都是 Vue Router 官方文档的常规写法。"

### 博客 bullet 2：动态路由 `/notes/:id` + 404 兜底

> "笔记列表点进详情，路由是 `/notes/:id`，这个 `:id` 是动态参数，详情页拿到它去数据里找对应那篇显示。另外配了一个兜底路由，路径没匹配到任何页面时就显示 404 页。"

**如果追问"刷新页面会不会 404"**（这是单页应用经典问题，旧口径 Q10 有现成答案）：
> "会有这个风险。因为整个站只有一个 index.html，history 路由下刷新深层链接，服务器找不到对应文件就 404。GitHub Pages 上我用了一个通用技巧：自定义一个 404 页面，先记住原本要去的地址，跳回首页再交还给前端路由还原。"

### 博客 bullet 3：数据抽离独立文件 + props 传给 NoteCard

> "内容不写死在页面里，单独放在 `src/data` 下的 JS 文件里，一个数组导出，页面 `import` 进来用。列表用 `v-for` 循环，每一项通过 props 传给 NoteCard 这个公共卡片组件显示。这样加一篇笔记只改数据文件，页面代码不用动。"

**如果追问"为什么不用数据库 / 接口"**：
> "纯展示内容，是我自己写的笔记和介绍，没有用户交互和动态数据，写死在 JS 文件里对静态站最简单，也免费好托管。以后真要频繁更新再考虑接接口。"

### 博客 bullet 4：CSS 变量主题 + Flex / 媒体查询响应式

> "手写 CSS，没用组件库，学习性质的项目想练布局基本功。主题色用 CSS 变量集中定义，改一处全站生效；布局主要用 Flex，配合媒体查询在窄屏下调整，适配手机和电脑。"

### 博客 bullet 5：GitHub Actions 自动部署到 Pages（你的王牌题）

> "代码推到 GitHub 的 main 分支，GitHub Actions 就自动跑：装依赖、打包成静态文件、发布到 GitHub Pages，全程不用手动操作。中间主要踩了一个坑——国内访问 GitHub 很慢，配了 hosts 加速解决的。"

**结尾主动把话题引向踩坑经历**（你真操作过、记得住），别让它顺势变成追问代码实现。

**如果被追（各一句就停）**：
- "npm ci 和 npm install 区别？" → "npm ci 严格按 lock 文件装，结果可复现，CI 环境推荐它。"
- "子路径问题？" → "Pages 上项目地址带仓库名前缀，打包时要把前缀告诉 Vite，不然静态资源路径找不到。"

## 四、防穿帮守则（背这 5 条）

1. **原理只说一句**，说完就停，等他问。说多了必被追两三层，容易露馅。
2. **不会就直说 + 带方向**："这个细节我记不清了，但思路应该是 XXX"——远好于硬编。
3. **不主动提深水区**：TS 高级类型、Pinia 响应式原理、防抖节流、接口请求、错误处理（书店是本地 mock，博客是纯静态无接口，本来就没有）。
4. **把书店的话题往博客部署经历引**：书店难点答完，补一句"其实让我收获更大的是博客部署上线整个过程"。
5. **演示准备好**：面试时打开博客线上地址边点边讲。真实流畅的演示比说一百句都可信。
