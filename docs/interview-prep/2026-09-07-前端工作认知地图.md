# 前端工作认知地图（一页看懂"前端到底干嘛"）

> 2026-09-07 定稿。目标：**不用深入**，但被问到"你了解前端工作吗""实习想做什么"时，
> 你能说出人话、像个入行的人，而不是只会背项目。
> 用法：读 2-3 遍，能对着下面每一块**用自己的话讲出来**就算过关。讲不出=没懂，重读。

---

## 0. 一句话定义

前端 = 把设计稿变成用户**能看到、能点、能用**的网页界面，保证它在不同设备/浏览器上正常跑，
数据从后端接口取来展示给用户。

---

## 1. 前端一天大概在干嘛（真实流程，按顺序）

1. **看需求 / 开晨会**：产品经理说要加个功能、改个页面
2. **看设计稿**：设计师给的图（Figma / 蓝湖），上面标了间距、颜色、字号
3. **切图 / 还原**：用 HTML + CSS 把设计稿写成网页，尽量 1:1 还原
4. **写逻辑 / 组件**：用 Vue / React 写交互（点按钮、弹窗、表单校验、列表）
5. **联调接口**：后端给你接口，你把返回的数据（JSON）显示到页面上
6. **改 bug**：测试或用户报的问题，定位 + 修复
7. **适配**：手机端 / 电脑端 / 不同浏览器都要正常显示
8. **提交代码**：Git commit → push → 提 PR/MR → 同事**代码评审** → 合并
9. **打包上线**：构建（`npm run build`）→ 部署到服务器 → 线上验证

> 你的博客走完了 3、4、8、9 的简化版，缺的是 1、2、5、6、7（需求、设计稿、联调、改 bug、适配）——
> 面试时大方承认"这些真实项目环节我还没经历过，想在实习里补"，反而加分。

## 2. 前端在公司里和谁打交道

| 角色 | 他给你什么 | 你给他什么 |
|---|---|---|
| 产品经理 | 需求（要做什么） | 反馈能不能做、要多久 |
| UI 设计师 | 设计稿 | 问细节、说还原难点 |
| 后端开发 | 接口（返回 JSON 数据） | 对接、联调、报字段问题 |
| 测试 | bug 单 | 修完回复、说明改了啥 |
| 前端同事 / 组长 | 分活、代码评审、答疑 | 提交代码、问不懂的 |

## 3. 真实项目 vs 你这个博客（心里要有数，可能被问）

| 维度 | 你的博客 | 真实工作项目 |
|---|---|---|
| 数据来源 | 写死在 JS 文件里 | 后端接口动态取 |
| 设计 | 自己排版 | 设计师给稿，要求还原度 |
| 协作 | 一个人 | 一个团队，要沟通 / 评审 |
| 代码管理 | 直接 push | 分支 + PR + 评审通过才合并 |
| 需求 | 自己定 | 产品定，还会频繁改 |
| 规模 | 几个页面 | 几十上百个页面 / 组件 |

**面试话术**：
> "博客是我一个人做的练手项目，从写页面到部署上线整套流程我自己走过一遍。真实项目里的
> 接口联调、设计稿还原、团队协作和代码评审我还没经历过，但流程我了解，想在实习里补上。"

## 4. 实习生进去大概先干嘛（别怕，所有人都从这开始）

改样式 / 调间距 → 切简单页面 → 写小组件 → 修小 bug → 跟着做一个完整小需求。
**没人一上来让你写核心代码**。所以"能改样式、能写小组件、能看懂别人代码"就是实习的入场券。

---

## 5. 认个脸：前端常用工具（不深入，能听懂、能说出用途就行）

- **VS Code**：写代码的编辑器
- **Chrome 开发者工具（F12）**：看元素、调样式、看接口请求、看报错——前端天天开着
- **Git / GitHub / Gitee**：代码版本管理、托管
- **npm**：包管理器，装依赖、跑脚本（`npm install` / `npm run dev`）
- **Vue**（你在学）/ **React**（另一大主流框架）
- **组件库**：Element Plus、Ant Design——别人写好的现成 UI，直接拿来用
- **Figma / 蓝湖**：看设计稿
- **Postman / Apifox**：调后端接口、看返回数据

## 6. 听懂"会议室黑话"（术语速查，能解释一句就行）

| 术语 | 意思 |
|---|---|
| 联调 | 前端和后端对接接口、一起把功能调通 |
| 切图 | 把设计稿做成网页 |
| 还原度 | 页面和设计稿像不像 |
| 组件库 | 现成的 UI 零件库（Element/AntD） |
| 脚手架 | 快速生成项目骨架的工具（Vite、create-vue） |
| 打包 / 构建 | 把源码编译成浏览器能跑的文件（`npm run build` → `dist`） |
| 上线 / 部署 | 把打包结果放到服务器让用户能访问 |
| 回滚 | 新版本出问题，退回旧版本 |
| 埋点 | 统计用户点了什么，数据上报给后台 |
| 兼容 | 不同浏览器 / 设备都能正常显示 |
| 响应式 | 一套页面自动适配大屏小屏（你博客里的 `@media` 就是） |
| 跨域 | 浏览器安全限制，前端请求别的域名被拦（后端配 CORS 解决） |
| 状态管理 | 复杂项目集中管数据（Pinia / Vuex，你现在不用会） |

## 7. 被问到时的三句人话（背下来，能自然说出）

- **"你对前端工作的理解？"**
  > "前端负责把设计稿变成能用的界面，和后端联调拿数据，保证各个端都正常，最后打包上线。
  > 我博客虽然小，但从写页面到部署上线整套流程自己走过一遍。"

- **"实习想学到什么？"**
  > "想接触真实项目——设计稿还原、接口联调、团队协作和代码评审，这些是我自己练项目练不到的。"

- **"为什么做前端 / 为什么选这行？"**
  > 结合她真实情况，简单真诚即可（例："我喜欢做出来能马上看到效果的东西"），**别编宏大理由**，
  > 面试官听得出真假。
