# 简化好背版：双项目面试口径（内部使用，不要外传）

> 配套：[2026-09-01-项目深挖双项目面试题-参考答案.md](./2026-09-01-项目深挖双项目面试题-参考答案.md)
>
> 这一版的原则：**每题 30 秒内讲完、大白话、不往深水区跳**。
> 两个项目两种口径：
> - **书店（毕设）**：坦诚是"模板二次开发"，讲你看得见的部分（功能、页面、交互），原理只留一句话
> - **博客**：讲“是什么”和“我做了什么”（页面功能、部署上线的亲身流程），不深入代码实现——部署那段你是真实操作过的，最有底气；代码层面统一口径“写法很常规”就够

---

## 第一招：统一开场口径（先把这个说稳）

面试官问"这项目是你独立做的吗"（或类似问题时），你的标准回答：

> “书店这个项目我是在一个开源模板的基础上做的二次开发，按毕设要求改了页面布局、加了留言板和个人中心这几个模块，后台数据是本地模拟的。模板本身的架构我是能看懂的，但让我从零再写一遍可能要花不少时间。博客是我自己搭的，跟着教程和资料一步步来，写法都是很常规的 Vue，最大的收获是走完了部署上线整个流程——代码托管、自动部署、还有国内访问 GitHub 的网络问题都是我自己解决的。”

**为什么这样说最安全**：
- 不撒谎（撒谎最容易被追问穿帮）
- 面试官听过太多"独立开发"的毕设了，坦诚二开反而显得真实
- 把火力引到博客的**部署经历**上（那段你真操作过、有真实细节），而不是博客的代码上——博客被问代码时同样守住“写法很常规”的口径

## 第二招：13 道题的极简口径

### Q1 介绍书店项目（30 秒版）

> "云海书坊，一个网上书店的网页应用。主要有四块功能：图书商城可以搜索、按分类筛选、看详情；有阅读专栏和留言板；个人中心里有购物车和收藏。技术上就是现在很主流的 Vue3 全家桶——Vue3 + TypeScript + Pinia + Vue Router，页面之间的跳转和登录验证靠路由守卫，购物车和登录信息用 Pinia 管，刷新不丢是存在了浏览器本地存储里。"

**被追问"为什么用这些技术"**：
> "Vue3 是现在招聘要求最多的框架，Pinia 是它官方推荐的状态管理，选型没太多纠结，就是主流方案。"

### Q2 组件怎么划分的（30 秒版）

> "通用的部分抽成公共组件，比如图书卡片、顶部导航、底部页脚，这些放 components 目录；每个页面是独立的视图组件放 views 目录；个人中心里还有几个子页面，用的是路由嵌套。数据的话，页面之间的共享状态走 Pinia，父子组件就是 props 传下去、事件传上来。"

### Q3 登录怎么实现的（30 秒版）

> "登录成功后把用户信息存在浏览器的 localStorage 里，然后路由有个全局守卫，每次跳页前检查目标页面要不要登录，要登录而没登录就跳到登录页，登录完再跳回原来想去的页面。"
>
> （主动补一句，堵住追问）"当然我知道这只是前端演示级的方案，真实项目密码不能这么存，应该后端校验、发 token，我毕设里没做后端所以用了简化方案。"

**主动说出"我知道这是简化方案"非常重要**——面试官本来想追问安全漏洞，你先说了，他基本就不再深挖，反而觉得你有安全意识。

### Q4 为什么用 Pinia（30 秒版）

> "因为购物车和登录状态要在好几个页面之间共享——列表页、详情页、个人中心都要读购物车。放 Pinia 里所有页面都能直接访问，而且它自带响应式，一个地方改了别的地方自动更新，不用我手动同步。相比老的 Vuex 它没有 mutations，写起来简单很多。"

### Q5 数据层设计（30 秒版）

> "数据请求都封装在 api 目录里，页面只管调用、不管数据从哪来。现在的数据是本地的 mock 数据，接口模拟了一点网络延迟，调用方式跟真实接口一样，以后要接真后端就只改 api 这一层，页面不用动。"

### Q6 购物车（30 秒版）

> "购物车就是一个 Pinia 里的状态数组，每项是图书加数量。加同一本书就数量加一，不重复添加；总价和总数是自动计算的；每次改动都同步写进 localStorage，刷新不丢。"

**被追问"有什么可以改进的"**（背这一句就够）：
> "金额计算用的浮点数，严格来说可能有精度问题，真实电商应该用分为单位存整数。"

### Q7 搜索防抖（30 秒版）

> "搜索框输入每个字都会触发查询，打'三体'两个字就发了好几次请求，很浪费。所以做了防抖：每次输入先取消上一次的定时器，等用户停顿 300 毫秒没再输入，才真正发请求。防抖是'等你做完再执行'，节流是'固定频率执行'，搜索适合防抖。"

### Q8 TypeScript（30 秒版）

> "主要用来定义数据结构——图书、用户、留言这些都有对应的类型，改字段名的时候编译器会直接报错提示哪里没改到。用的是基础用法：接口定义、ref 标注类型这些。"

**如果追问高级用法（Omit/Partial 之类）**：
> "模板源码里用了一些工具类型，我能看懂作用，但自己写还不熟。" —— 诚实且无害。

### Q9 博客怎么上线的（你的王牌题，40 秒版）

> “代码托管在 Gitee 和 GitHub 上。GitHub 那边配了自动部署：推代码到 main 分支，GitHub Actions 就自动打包发布到 Pages，全程不用手动操作。另外在 Vercel 也部署了一份当备用地址，两边代码一样。中间主要踩了两个坑：一个是国内访问 GitHub 很慢，配了 hosts 加速解决的；另一个是单页应用刷新会 404，这个是部署静态单页应用的经典问题。”

**结尾那句是故意的钩子**——主动把面试官引向 404 问题，而 404 你在 Q10 有现成的简单答案，等于把追问引到你准备好的题上。

**被追问（各一句话就停）**：
- “npm ci 和 npm install 区别？” → “npm ci 严格按 lock 文件安装，结果可复现，CI 环境推荐它。”
- “子路径问题？” → “Pages 上项目页面地址带仓库名前缀，打包时要把前缀告诉 Vite，不然静态资源路径会找不到。”
- “hosts 加速什么原理？” → “手动把 GitHub 域名指定到响应快的 IP，绕过 DNS 解析慢的问题。”

### Q10 刷新 404（30 秒版）

> "网页只有一个 index.html，history 路由下刷新深层链接，服务器找不到对应文件就 404。两个方案：Vercel 上配置把所有路径都重写回 index.html；GitHub Pages 不支持这个，我用了一个社区通用的技巧——自定义一个 404 页面，先记住你原本想去的地址，跳回首页再还原给前端路由。书店项目用的 hash 路由，井号后面的内容不会发给服务器，天然没这个问题。"

### Q11 v-html 风险（30 秒版）

> "v-html 会把字符串当 HTML 执行，如果内容来自用户输入，别人就能塞恶意脚本进去，这就是 XSS。所以项目里只有文章内容这种固定的富文本用 v-html，用户输入的留言都是用双花括号插值，它会把内容当纯文本显示，天然安全。"

### Q12 性能优化（30 秒版）

> "已经做的是路由懒加载，每个页面单独打包，访问哪个才加载哪个。图片可以再加懒加载和压缩。真要系统性优化的话我会先用 Lighthouse 跑个分看瓶颈在哪，而不是凭感觉改。"

### Q13 最难的是什么（30 秒版，二开人设专用）

> "最难的是读懂模板的架构再动手改。一开始我在别人的代码上改样式，经常牵一发动全身。后来我先花时间把项目结构和数据流向理清楚了才敢动手，之后加留言板这些功能就顺了。这个经历让我体会到：改别人代码之前先读代码，比上来就写更重要。"

**如果再做一遍会改什么**：
> "会早点接一个真后端接口试试，比如用 json-server，毕设里全是本地数据，网络请求和错误处理没得到锻炼。"

## 第二招·补：博客专项口径（面试官对“你自己的项目”必问的几题）

### B1 介绍一下你的博客

> “一个求职用的作品集网站，相当于在线简历加学习记录。四个页面：首页、关于我、学习笔记、项目展示。技术上就是很常规的 Vue3 + Vite，页面切换用路由，内容写在本地 JS 文件里，纯静态不需要后端。已经上线了，GitHub Pages 和 Vercel 各放了一份。”

**被追问“为什么不用后端”**：
> “内容就是我自己写的笔记和介绍，没有用户交互和动态数据，纯静态最合适——免费托管、加载快、不用维护服务器。”

### B2 为什么做这个博客？

> “两个目的：一是把简历内容做成能点开的网页，面试时直接发链接，比 PDF 有说服力；二是把学习笔记和面试题放进去，边学边攒，平时也是自己的复习工具。”

### B3 博客的难点 / 收获是什么？

> “写代码本身不难，都是常规写法。最大的收获是走完了从写代码到网站上线的完整流程——Git 推送、自动部署、双平台上线，还有排查国内访问 GitHub 慢的过程。以前只是会写页面，现在知道一个网站是怎么真正跑起来的。”

### B4 博客的数据怎么存的？

> “写在项目里的 JS 文件中，一个数组导出，组件 import 进来用。加一篇笔记就往数组里加一条，重新部署就更新了。”

**被追问“为什么不用数据库 / 接口”**：
> “纯展示内容，写死在 JS 文件里对静态站最简单。以后真要频繁更新再考虑接接口。”

### B5 为什么手写 CSS 不用组件库？

> “学习性质的项目，想练布局基本功。主题色用 CSS 变量统一管理，改一处全站生效。”

### B6 博客和书店技术几乎一样，区别在哪？

> “书店是模拟的有状态交互（登录、购物车），博客是纯展示。书店用 TypeScript 和 Pinia 多一些；博客更简单，我的重点放在部署上线上了。”

## 第三招：防穿帮守则（记住 6 条）

1. **原理只说一句话**。说多了必然被追问，追问两三层就容易露馅。说完就停，等他问。
2. **不会就直说，但带个方向**："这个细节我记不清了，但思路应该是 XXX"——远好于硬编。
3. **不主动提**：TS 高级类型、Vuex/Pinia 源码、单元测试、订单模块、10 万条数据优化。这些是深水区，提了就要接得住。
4. **把话题往博客的部署经历引**：面试官问书店的难点，答完补一句“其实让我收获更大的是博客部署上线的整个过程”——引向流程和踩坑（你真操作过），别让它顺势变成追问博客的代码实现。
5. **演示准备好**：打开两个线上地址，边点边讲。演示真实流畅，比口头说一百句都管官信。
6. **博客被问代码细节时**：口径是“写法很常规”——组件就是页面加公共导航页脚，路由就是官方文档的写法。别主动提架构性的词（数据模块解耦、CSS 设计体系之类），说了就要接得住“为什么这样设计”。

如果只背三题，背这三个（其他可以现场发挥）：
