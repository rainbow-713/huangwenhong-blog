## 第 2 步：把三篇数据放进 ref（约 15 分钟）

**打开哪里：**脚本内，替换提示注释。数组结构已经练过，新的只是外面用 `ref(...)` 包起来。

```js
import { ref } from 'vue';

const notes = ref([
  {
    id: 101,
    title: '认识 HTML',
    summary: 'HTML 用来描述网页结构。'
  },
  {
    id: 203,
    title: '练习 CSS',
    summary: 'CSS 用来调整颜色和间距。'
  },
  {
    id: 305,
    title: '点击按钮',
    summary: 'JavaScript 可以响应点击。'
  }
]);
```

只认清四层：
- `ref(...)`：Vue 的响应式容器，这次里面装数组。
- `[ ... ]`：数组，按顺序装三篇。
- `{ ... }`：一篇对象，装编号、标题、摘要。
- `title`、`summary`：各篇的属性。

脚本里取数组是 `notes.value`；今天模板里直接用顶层 ref 的 `notes`。Day03 没用 ref，才直接在脚本里用 `notes.length`，不要两套写法混在一起。

**做对时看到：**仍然一张占位卡片，画面不会仅因声明数组就自动出现三张。

**没对上，先检查：**数组末尾是 `]);`；相邻对象之间有逗号；是否多保留了另一份 `const notes`。

## 第 3 步：让总数来自数组（约 10 分钟）

**打开哪里：**模板里的“待计算”那一行，整行替换为：

```html
<p>笔记总数：{{ notes.length }}</p>
```

**做对时看到：**总数 3，但下面仍是一张占位卡片。总数显示和列表生成是两件事。

**没对上，先检查：**是不是 `length` 拼错；是否加了不需要的 `()`；是否在模板中写了 `notes.value.length`。

先问自己：“若只把总数手写成 4，数据真的变多了吗？”答案要指向数组，而不是数字好不好看。

## 第 4 步：用一份模板描述每一篇（约 20 分钟）

**打开哪里：**模板中从 `<article class="note-card">` 到 `</article>` 的整个卡片块。

**只替换这一块，保留外面的标题和总数：**

```html
<article v-for="note in notes" :key="note.id" class="note-card">
  <h2>{{ note.title }}</h2>
  <p>{{ note.summary }}</p>
</article>
```

一段一段读：
1. `notes`：要遍历的整份数组。
2. `note in notes`：每次取出一篇，临时叫作 `note`；它不是另一份固定数据。
3. `v-for`：为每一项渲染这张卡片及里面的内容。
4. `note.title`、`note.summary`：取当前这一篇的标题、摘要。
5. `:key="note.id"`：给当前这张卡片一个来自数据的身份标记。

**做对时看到：**三张不同内容的卡片，总数 3。代码里只有一份 `article` 模板。

**没对上，先检查：**
- 仍只一张：`v-for` 有没有写在卡片外层 `article`？
- 三张标题都一样：是否写死标题，或一直读取 `notes[0].title`？
- 标题重复但摘要各不相同：两处是否都用当前项 `note`？
- 报变量未定义：`note` 是否拼错，或被写到了循环块外？

`note` 这个名字可以换，但要把循环内部的引用一起改；今天不要求改名。别因为 `notes` 多一个 s，就只凭单复数背代码，要能指出“整组”和“当前一篇”。

## 第 5 步：编号、下标和 key 各干什么（约 15 分钟）

**打开哪里：**同时看数组中的 `id` 和模板 `:key`，不急着动手。

| 东西 | 本例 | 含义 |
|---|---|---|
| 数组下标 | 0、1、2 | 这一刻放在第几个位置 |
| 数据编号 | 101、203、305 | 哪一篇笔记，同一篇换位置也不换编号 |
| `:key="note.id"` | 每张取自己的编号 | 帮助 Vue 在列表变化时对应前后的项 |

冒号 `:` 是 `v-bind:` 的简写，表示这里使用 JavaScript 表达式的值。`:key="note.id"` 会分别取出 101、203、305；`key="note.id"` 没有冒号，是每项都叫同一个字面字符串。

只记两条要求：
- 同一层列表中，每篇 `id` 唯一，不能重复。
- 同一篇身份不变时，编号稳定；换顺序不重编号，不每次渲染随机生成。

`key` 不负责自动排序、去重或生成卡片，生成卡片的是 `v-for`。如果去掉 key 或重复 key，简单静态列表可能暂时看起来没问题；这不证明写法可靠，也不把“立刻画面坏掉”当作验收要求。今天不学 diff 源码。

**做对的标准：**能指出第二篇编号是 203，但当前位置下标是 1；将整篇挪动后，它的 `id` 不应该跟着位置变。

**没说清，先补：**用纸写三张带编号的笔记，交换位置，问“这还是不是原来的那一篇”。不需要背“key 优化性能”这类空话。

## 排错与求助

| 现象 | 优先检查 |
|---|---|
| 三张同样的标题 | 是否误用固定文字或 `notes[0]`，应读取当前项 |
| `note` 未定义 | 名字是否一致，是否在对应 `v-for` 的范围内 |
| 列表数量不对 | 数组真正有几个对象，是否额外复制了一张静态卡片 |
| 重复 key 警告或异常更新 | `id` 是否重复，是否少了冒号变成固定字符串 |
| 加第四篇报语法错误 | 对象间逗号、数组和 ref 的收尾 `]);` |
| 模板总数报错 | 模板中直接用顶层 `notes.length`，不是 `notes.value.length` |

求助：“Day06 第__步，我的数据有__项，画面有__张；相关数组和模板如下。请先让我找整组数据与当前项，不直接给完整组件。”

哥哥先看“数量来自数组、内容来自当前项”是否说得通，再问编号；不要用能否背诵 key 的定义代替理解。见 [理解验收指南](./给哥哥-前七天理解验收指南.md)。
