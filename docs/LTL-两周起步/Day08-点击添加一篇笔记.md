## 第 3 步：先检查标题能不能添加（约 15 分钟）

**打开哪里：**脚本中数组声明结束的 `]);` 后面、`</script>` 前面。新增：

```js
let nextId = 306;

function addNote() {
  const cleanTitle = title.value.trim();
  if (cleanTitle === '') {
    return;
  }
}
```

先不绑按钮，这个函数暂时也还没有添加动作。

逐行读，不要求背：
1. `nextId` 保存下一篇准备使用的编号；初始三篇最大编号是 305，所以下一个从 306 开始。
2. `let` 允许以后给 `nextId` 重新赋一个数字。它目前不直接显示在模板里，所以这里不需要 ref。
3. 点击函数执行时，`title.value` 读当时的输入。
4. `.trim()` 返回去掉两端空白后的新字符串，不删除中间空格，也不会自动改掉输入框的数据。
5. `cleanTitle` 是这一次执行中处理好的文字，定义在函数里；每次调用会重新读取最新输入。
6. `===` 是严格相等比较，不是赋值。与 `''` 比较是在问“清理后是不是空字符串”。
7. `if` 条件成立才进入大括号；`return;` 在这里是结束本次函数，后面的添加动作不再执行。

在纸上先填右边，再看参考：

| 输入 | `trim()` 得到 | 能否继续添加 |
|---|---|---|
| `''` | `''` | 不能，提前返回 |
| `'   '` | `''` | 不能，提前返回 |
| `'  周末练习  '` | `'周末练习'` | 能 |
| `'学习 Vue'` | `'学习 Vue'` | 能，中间空格保留 |

**做对时看到：**页面还和之前一样，按钮无新增效果。此刻没有绑定是正常阶段，不是失败。

**最小排错：**只有一份 `nextId`、一份 `addNote`；`===` 不要写成 `=`；`return` 在函数里；代码放在 `</script>` 前，不放到数组里面。

## 第 4 步：把一个完整对象放进数组（约 20 分钟）

**打开哪里：**刚写的 `addNote` 函数。在 `if` 块结束的 `}` 后、函数最后的 `}` 前新增下面这段代码。不要放进 `if` 块，否则只有空标题才会走到错误的位置。

```js
notes.value.push({
  id: nextId,
  title: cleanTitle,
  summary: '这是我今天添加的笔记。'
});
nextId = nextId + 1;
title.value = '';
```

这是三个执行步骤：向数组放对象 → 准备下一个编号 → 清空草稿。对象中的三个属性不是三次新增。

- `.push(...)`：把括号里的对象追加到数组末尾，直接改变这个数组。
- `id: nextId`：把当前编号数字存进新对象；随后 nextId 加一，不会把已经存入旧对象的编号一起改掉。
- `title: cleanTitle`：把清理过的文字存入新对象，不是固定字符串 `'cleanTitle'`。
- 摘要暂时是固定文字，今天不加第二个输入框。
- `title.value = ''` 通过已有 `v-model` 清空输入；已加入对象的标题字符串不会被清空。

**特别不要写：**`notes.value = notes.value.push(...)`。`push` 的返回值是新长度，不是新数组；不需要把它再赋给 notes。

完成后，函数整体应为以下顺序。**先自己检查，再展开对照；这是核对片段，不要追加第二份函数。**

<details>
<summary>检查括号或位置时展开：添加函数核对版</summary>

```js
function addNote() {
  const cleanTitle = title.value.trim();
  if (cleanTitle === '') {
    return;
  }
  notes.value.push({
    id: nextId,
    title: cleanTitle,
    summary: '这是我今天添加的笔记。'
  });
  nextId = nextId + 1;
  title.value = '';
}
```

</details>

**为什么 `nextId` 不放进函数？**放进去会每次从 306 重新开始。本例放在组件脚本顶层，同一组件实例里的多次点击共享它；新实例才重新初始化。

**为什么不用数组长度当编号？**篇数是“现在有几篇”，不是“哪些号码已经用过”。明天删除后篇数会变少，重新按长度取号可能撞上旧编号。今天的递增策略只适用于本地、固定初始数据、单实例练习，不是通用数据库编号方案。
