## 第 3 步：includes 只回答“包含吗”（约 10 分钟）

下面是阅读用的小例子，不必粘进组件。先猜 true/false，再看右边：

| 表达式 | 结果 | 原因 |
|---|---|---|
| `'认识 HTML'.includes('HTML')` | true | 含有连续的 HTML |
| `'认识 HTML'.includes('CSS')` | false | 不含 CSS |
| `'认识 HTML'.includes('html')` | false | 区分大小写 |
| `'认识 HTML'.includes('')` | true | 任何字符串都包含空字符串 |

`includes` 不会自动修改标题，也不会返回一篇笔记；它返回一个布尔值，正好可以交给 filter 决定是否保留当前项。

如果不知道 true 在这里意味着什么，先回 Day09 的保留判断表，不急着背 computed。

## 第 4 步：用 computed 保存“怎么算”，不是只算一次（约 25 分钟）

### 4.1 改导入（约 5 分钟）

**打开哪里：**脚本已有的 Vue 导入，整行替换为：

```js

```

不是再加另一份相同导入，不要重复声明 ref。

### 4.2 增加筛选规则（约 15 分钟）

**打开哪里：**在 `keyword` 和 `notes` 都已声明之后、所有已有动作函数外，新增：

```js
const filteredNotes = computed(function () {
  const word = keyword.value.trim();
  if (word === '') {
    return notes.value;
  }
  return notes.value.filter(function (note) {
    return note.title.includes(word);
  });
});
```

此时先不改循环。按层读：
1. `computed(function () { ... })`：交给 Vue 一条计算规则，结果依赖里面读到的响应式数据。
2. `word`：当次计算用的、去掉两端空白的关键词；不会把输入框里原始的空格自动删掉。
3. 空词：直接返回完整列表。本规则把“空词显示全部”明确写出来，便于阅读。
4. 非空：从完整的 `notes.value` 开始，filter 保留标题包含关键词的项。
5. 最内层的 `return` 给 filter 一个布尔值；外层的 `return` 给 computed 一个数组。这两个返回值用途不同。
6. `filteredNotes` 是派生结果：由原始列表和条件算出来，不是另一份手动维护的原始数据。

当前模板还没用结果，所以列表仍可能是三篇；下一步连接后再看筛选效果。

### 4.3 为什么不是普通 const（约 5 分钟）

如果只在 setup 执行一次 `const result = notes.value.filter(...)`，以后输入变了，这行普通 JavaScript 不会自动再执行。computed 会跟踪本次计算中读取的响应式依赖；依赖改变后，在结果被需要时重新计算，并缓存结果。

今天只需要能解释“关键词或相关列表数据变化，会得到新结果”，不背缓存源码，不添加 watch。

**绝对不要在这里写：**`notes.value = notes.value.filter(...)`。那会丢掉原始完整列表，清空关键词也找不回被覆盖的数据。

**也不要：**在 computed 里递增编号、添加笔记或清空输入。它只负责计算返回结果，修改数据的动作仍由按钮函数完成。
