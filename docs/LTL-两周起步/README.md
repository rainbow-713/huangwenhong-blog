## 一、这两周做到什么程度

### 争取拿到的成果

1. 一个自己做的笔记小练习：按钮有反应、数据能生成列表、输入能影响结果。
2. 博客笔记页的一项真实修改：按标题搜索，清空恢复全部，没有匹配时有提示。
3. 能演示、解释、改动这段实现，而不是只背“我用了 Vue3”。

如果基础练习卡住，就缩减功能。**第 14 天如实验收，不把日历走完当作技术学会。**能完成这些也不代表已经覆盖普通前端岗位的全部要求。

### 本轮先不做

- 整个博客重写、整文件默写、十道手写题限时测试。
- 防抖、节流、递归深拷贝、框架源码和复杂原理追问。
- TypeScript、Pinia、登录、数据库、后端、本地持久化。
- 为显得项目复杂而继续堆功能、装修页面或修改部署配置。

面试表达每天最多花 10～15 分钟，讲当天确实做过的内容；当天没做明白，就不额外背一批新题。

## 二、每天怎么学：一个小动作，一个结果

每天约 2～3 小时核心练习是**排课假设，不是已经确认的可用时间**。可分成两段做；每 30～40 分钟休息一下，休息时间另算。多出的时间用于变式、复习和纠错，不额外塞新章节。

| 环节 | 建议用时 | 只做什么 |
|---|---|---|
| 找回昨天 | 10 分钟 | 打开自己的成果，演示一个功能，尝试改一个字或条件 |
| 小步练习 | 60～90 分钟 | 每步约 5～20 分钟：看示范、动手、保存、观察，不整章刷视频 |
| 独立变式 | 20～30 分钟 | 合上当前题的完整示范，换一个要求，允许查语法 |
| 排错与记录 | 20～30 分钟 | 检查行为，保存源码与真实记录；Day07 起提交、推送，再发提交链接 |

练习循环始终是：**看一个小示范 → 自己完成 → 观察结果 → 改一个条件 → 用自己的话解释。**

- HTML/CSS 起始骨架可以复制，已经会的布局不必每天重敲。
- 当天新学的交互逻辑自己输入、修改、运行。手敲不是最终判据，能做变式才更能说明理解。
- 可以查语法、问人、问 AI。照着答案完成记作“示范后完成”，不能记作“独立完成”。
- 卡住约 10～15 分钟还没推进，就整理问题求助；不等哥哥晚上回家，也不独自耗一整天。
- 当天超时：保存已经做出的部分并记录卡点；Day07 起再按流程回传。停下扩展任务，不熬夜补齐表格。
- Day07 首次 Git 准备占用当天扩展时间，不额外延长两周。推送受权限或网络阻碍时先保存，明确报“待补交”，不能把它当作已经交付。

### 首次准备

Day07 第一次交作业时做一次；已经有自己的练习分支也先检查，不重复创建。先做这一步，再在仓库新建当天作业。已有未提交作业先在仓库外备份，按下面检查处理，不直接覆盖或清空。

哥哥提前确认一次即可：接收作业的仓库地址、妹妹账号的写权限、`ltl-practice` 是否可由她使用。能拉取不代表能推送；`git remote -v` 也只能显示地址，不能证明写权限。哥哥暂时没回复时，按 [Day07 的临时保存办法](./Day07-输入标题并做第一周复习.md#practice-setup)继续练习，不尝试改远程或绕过权限。

1. VS Code 打开你平时拉取任务的博客根目录，不是单独打开 `docs` 或 `practice`。应同时看到 `package.json`、`src`、`docs`。
2. 保存编辑器未保存的文件。打开“终端 → 新建终端”，使用 Windows PowerShell。
3. 下方命令**一条一条执行，上一步成功才做下一条**。看到错误就停，不把整段盲贴进去。

```powershell
git --version
git rev-parse --show-toplevel
git status --short
git branch --show-current
git remote -v
```

| 命令结果 | 怎样判断 |
|---|---|
| `git --version` | 能看到版本号，只说明 Git 命令可用 |
| `git rev-parse --show-toplevel` | 路径是这份博客根目录，而不是桌面练习目录 |
| `git status --short` | 无输出表示工作区与暂存区没有待处理变化；不是命令没执行 |
| `git branch --show-current` | 记下当前分支；此时可能是 `main`，稍后再切换 |
| `git remote -v` | 核对 `origin` 的 fetch、push 地址；不能把令牌贴到作业 |

检查：根目录应是这份博客；`git status --short` 应没有输出；远程 `origin` 应指向哥哥更新任务、并允许你写入的同一个仓库。GitHub 和 Gitee 不是自动互通的两个入口，先和哥哥确认这次以哪一个接收作业，不自行更换远程或同时推两个平台。

- 状态不为空：先看每个文件。已有作业、别人的修改、暂存区内容都要保留；请哥哥或 AI 帮忙确认怎样安全转入练习分支，不能为得到“干净状态”丢弃文件。
- 没有 Git、不是仓库、没有 `origin` 或账号没写权限：按[卡住处理](#homework-help)求助。不要在练习目录执行 `git init`，也不要重新下载一个空项目。
- 远程地址若含凭据，不把输出原样公开。后面的 `origin`、`main` 只适用于检查通过的仓库；名称不同先求助核对。

确认后运行：

```powershell
git fetch origin
git branch --list ltl-practice
git branch --remotes --list origin/ltl-practice
```

`fetch` 下载远程信息，不会直接覆盖你的工作文件。根据两条分支查询结果，**只选一行执行**：

| 当前情况 | 命令 |
|---|---|
| 已有自己的本地 `ltl-practice` | `git switch ltl-practice` |
| 本地没有，远程已有自己的 `origin/ltl-practice` | `git switch --track -c ltl-practice origin/ltl-practice` |
| 本地和远程都没有，准备首次创建 | `git switch --no-track -c ltl-practice origin/main` |

首次创建的 `--no-track` 避免把作业分支的上游误设为 `origin/main`；首次推送时再连接远程练习分支。若提示分支已存在、找不到 `origin/main` 或切换会覆盖文件，停止求助，不改用强制选项。成功后运行 `git branch --show-current`，必须显示 `ltl-practice`，再按下一节同步任务。首次配置多花的时间从当天选做里扣，不额外加课。

```powershell
git status --short
```

必须是 `ltl-practice`，而且状态为空。若还有昨天的改动，先按[提交流程](#homework-push)保存、检查、交付真实进展；不确定归属就停下求助，不在脏工作区继续合并。

```powershell
git fetch origin
git branch --remotes --list origin/ltl-practice
```

若查询显示远程练习分支，先执行下面一条；首次还没推送、查询为空时跳过：

```powershell
git merge --ff-only origin/ltl-practice
```

成功后再把哥哥的新任务合入你的练习分支：

```powershell
git merge --no-edit origin/main
git status --short
```

第一条合并同步同一练习分支的远程进展；第二条把 `main` 的更新带进来，**不是把作业合并回 `main`**。它可能产生一条合并提交，属于正常同步，不算你完成了新练习。状态为空后重新打开当天任务，才开始修改。

遇到 `CONFLICT`、`not possible to fast-forward` 或其他错误就停下，不继续敲后续命令；保留现场按[卡住处理](#homework-help)求助，不随便选“全部接受”。

<a id="homework-push"></a>

### 练习结束后提交并推送

Day07～Day12 文件提供当天的 `git add` 路径和提交消息示例。首次可跟着 [Day07 提交实操](./Day07-输入标题并做第一周复习.md#first-push)逐步走，熟悉后查本节。没有完成也交当前源码与卡点；若当天只补练旧题，把当天练习副本放在当天目录并指出来源，不要求补交以前整份作业，不为凑记录创建空答案。

1. **保存。**Day07～Day11 把演练场的最新内容复制到本地对应文件，按 Ctrl+S；Day12 保存实际修改的博客源码，不用演练场代码覆盖它。确认 `完成记录.md` 的实际结果对应这份代码；变式已恢复时注明恢复前后分别验证了什么。
2. **检查。**在仓库根目录执行下方命令，确认分支仍是 `ltl-practice`，暂存区最初为空，改动范围属于自己的作业。

```powershell
git branch --show-current
git status --short
git diff --cached --stat
```

3. **暂存。**按当天任务的 `git add -- 指定路径` 选择文件。这一步是挑选这次要交的内容，不是上传；不要使用 `git add .` 或“暂存全部”。已有不明暂存内容先停下确认。

4. **核对。**执行下方命令，检查完整差异。`git diff --cached` 包括刚暂存的新文件；若进入分页界面，按 `q` 退出，也可在 VS Code“暂存的更改”逐个查看。

```powershell
git diff --cached --stat
git diff --cached
```

只应出现当天作业与明确属于本次的源码。Day07～Day11 不应混入 `src`、任务文档、锁文件、部署配置、`node_modules` 或 `dist`。误暂存时仅在确认归属后取消对应文件的暂存，不丢弃工作内容。

5. **提交。**使用当天给出的 `git commit -m "…"` 示例，并按实际状态写“提交进展”或“完成练习”。`commit` 只记在本地，哥哥此时还看不到。
6. **推送。**提交成功后执行：

```powershell
git push -u origin ltl-practice
```

这条命令明确把练习分支推到已确认的仓库；后续也可沿用，不改成 `main`。如果提交失败、网络失败或推送被拒绝，停止并记录“未提交”或“已提交、待推送”，不要强推、跳过检查或宣称已交付。

7. **确认远程。**在浏览器打开实际接收作业的仓库，切换到 `ltl-practice`，打开刚才的提交详情。用 `git log -1 --oneline` 核对最新提交编号，查看分支中的源码和完成记录确实是本次版本，再复制该提交的网页链接；只改记录时，源码不一定出现在本次差异里，不用为此制造改动。
8. **发给哥哥。**“Day__ 第__步，已推送：提交链接；实际完成__；还卡在__。”哥哥没空时继续按前置检查学习，不等回复，但待补交的网络或权限问题仍要跟进。

保存、commit、push 是三个不同动作。没有新改动时不制造空提交；同一天继续练习，就更新原目录和记录再正常提交，不修改或伪造过去的提交时间。

### 卡住时怎么处理

| 现象 | 下一步 |
|---|---|
| 提示没有提交者姓名或邮箱 | 请哥哥或 AI 协助设置你自己的提交身份，不冒用哥哥身份 |
| 没写权限、认证失败 | 确认登录账号与协作者权限；不把密码、令牌发进聊天或作业 |
| 推送被拒绝、分支分叉 | 保留本地提交，发分支名和脱敏错误；请人检查远程差异，不强推 |
| 合并冲突 | 不随意删标记或覆盖整文件，先确认两边改动；不执行后续提交命令 |
| 路径不存在或远程没看到作业 | 检查终端根目录、文件是否保存、实际分支与仓库、是否只 commit 没 push |
| Git 问题一时解决不了 | 源码在本地及仓库外留备份，发卡点与文件作为临时求助；标待补交，继续不依赖 Git 的练习 |

可复制这段求助，不贴密钥：

```text
我在博客仓库提交自己的练习，不是要部署。
当前步骤：______；分支：______；git status --short：______。
执行的命令与脱敏错误：______；源码已保存到______。
请先只读检查目录、分支、暂存和远程关系，再给一个最小处理步骤。
不要强推、丢弃改动、覆盖文件、改写提交历史或替我写学习结果。
涉及权限或合并冲突，先说明需要确认什么，等我确认。
```

### 哥哥如何异步验收

打开提交链接，先看 `完成记录.md`，再看她指出的源码变化；需要复现时用对应源码和演练场链接。Day12 要在完整博客中复现，不能把单页快照直接放进演练场。

- 只想确认进度：看实际文件、操作结果与卡点，不要求当天在线演示。
- 想检查理解：从本次改动挑一个小条件，文字问预测，让她再修改、运行并回传结果。提交过、页面跑通都不单独证明理解。
- 给反馈时分清“已收到／尚未验收／这一项已有证据／仍需补练”。不为验收而每天合并作业。

[当前 Pages 工作流](../../.github/workflows/deploy.yml) 在推送 `main` 时触发部署。练习分支不触发这条 Pages 工作流；其他平台是否自动预览需单独核对，不能把分支当作保密空间。公开仓库的作业也可能被任何人看到。

Day12 功能是否合并到 `main`，由哥哥看过差异与测试后再决定；本轮不要求学生发布，也不替她执行提交或推送。

- 前几天同步核实学籍、毕业证类型、预计毕业时间和可实习时长。五年制不能只按年数判断学历，也不照背旧文档的“中专”口径。
- 收集匹配的真实岗位要求、学校就业渠道和实习机会，不等教程全部刷完才了解招聘。
- 有能独立演示和修改的小功能后，可以开始针对性投递并记录反馈；这不保证录用，未掌握的能力要如实说明。
- 简历只写自己确实完成且能解释的内容，区分初版 AI 辅助搭建和自己的后续修改，未独立完成的部分不写“从零独立开发”。
- 接口请求、加载与错误状态等仍是本轮缺口。根据岗位需求和实测表现决定后续优先级，不临时全部塞进这两周。
- 不因赶时间接受培训贷、先付费才能入职等条件。

## 八、下一次怎么继续

按上方 Day01～Day12 的入口逐步练，每天先做前置检查，不用一次读完全部文档，也不把提前生成文档当作学生已完成。

接下来细化 Day13～Day14 时，带上实际代码、卡住的步骤、Day11 分项记录，以及 Day12 搜索、详情往返和构建是否做过的真实结果。哥哥没来得及抽查的项目如实标注即可。
- 数组、输入、筛选关系能解释，也能改一个小条件验证：继续在博客做边界测试和同类规则变式。
- 因果清楚、只是语法不熟：可以带自己的代码和语法小抄，不以默写作为推进门槛。
- 有方向但需要提示：下一次先补一个同类小动作，再决定是否推进。
- 关键关系仍断开：只补对应动作，缩减后续扩展，不延长两周上限，也不让 AI 代写作业。
