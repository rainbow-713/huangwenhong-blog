> 起点：目前最多能独立写一张静态卡片。周期：最多 14 天。主线：笔记卡片 → 小交互 → Vue 笔记列表 → 博客里的真实修改。
> 这是一轮入门训练，不是“14 天包就业”，也不要求两周学完所有 Vue3 功能。

## 一、这两周做到什么程度

### 争取拿到的成果

1. 一个自己做的笔记小练习：按钮有反应、数据能生成列表、输入能影响结果。
2. 博客笔记页的一项真实修改：按标题搜索，清空恢复全部，没有匹配时有提示。
3. 能演示、解释、改动这段实现，而不是只背“我用了 Vue3”。

如果基础练习卡住，就缩减功能。**第 14 天如实验收，不把日历走完当作技术学会。**能完成这些也不代表已经覆盖普通前端岗位的全部要求。

### 本轮先不做

- 整个博客重写、整文件默写、十道手写题限时测试。
- 防抖、节流、递归深拷贝、框架源码和复杂原理追问。
- TypeScript、Pinia、登录、数据库、后端、本地持久化。
- 为显得项目复杂而继续堆功能、装修页面或修改部署配置。

面试表达每天最多花 10～15 分钟，讲当天确实做过的内容；当天没做明白，就不额外背一批新题。

## 二、每天怎么学：一个小动作，一个结果

每天约 2～3 小时核心练习是**排课假设，不是已经确认的可用时间**。可分成两段做；每 30～40 分钟休息一下，休息时间另算。多出的时间用于变式、复习和纠错，不额外塞新章节。

| 环节 | 建议用时 | 只做什么 |
|---|---|---|
| 找回昨天 | 10 分钟 | 打开自己的成果，演示一个功能，尝试改一个字或条件 |
| 小步练习 | 60～90 分钟 | 每步约 5～20 分钟：看示范、动手、保存、观察，不整章刷视频 |
| 独立变式 | 20～30 分钟 | 合上当前题的完整示范，换一个要求，允许查语法 |
| 排错与记录 | 20～30 分钟 | 检查行为，本地保存文件；平时发三句文字，需要时再补演示 |

练习循环始终是：**看一个小示范 → 自己完成 → 观察结果 → 改一个条件 → 用自己的话解释。**

- HTML/CSS 起始骨架可以复制，已经会的布局不必每天重敲。
- 当天新学的交互逻辑自己输入、修改、运行。手敲不是最终判据，能做变式才更能说明理解。
- 可以查语法、问人、问 AI。照着答案完成记作“示范后完成”，不能记作“独立完成”。
- 卡住约 10～15 分钟还没推进，就整理问题求助；不等哥哥晚上回家，也不独自耗一整天。
- 当天超时：保存已经做出的部分，记录卡点，停下扩展任务，不熬夜补齐表格。

## 三、在哪里练：先少碰环境，再回到博客

### Day01～Day03：独立 HTML 文件

在自己电脑上建 `前端练习/day01/index.html`，随后每天建对应目录保存练习。用 VS Code 编辑，普通浏览器打开。

- 不需要 npm，不修改博客的 `index.html`。
- 普通文件保存后，需要在浏览器刷新；文件未保存，浏览器就读不到新内容。
- Day01～Day02 观察点击触发的变化；Day03 观察脚本读取数据并写入页面。保存、刷新会重新运行脚本，不等于 Vue 响应式。

### Day04～Day11：Vue 官方演练场

使用 [Vue 官方单文件组件演练场](https://play.vuejs.org/)。统一使用 JavaScript 和 `<script setup>`，不同时学习 `data()`、`methods` 那套选项式写法。

- Day04～Day08 提供最小起始结构，Day09～Day11 从自己的成功副本接着改，不要求自己搭建 Vite 项目；每天切换练习前先把当前组件保存到本地。
- 每天将演练场中自己编辑的组件内容复制保存到当天目录，例如 `day04/App.vue`；若拆了组件，每个文件都保存，名称保持一致。
- 保存当日演练场的分享链接作为补充，但不能只留下浏览器标签页。
- `.vue` 文件不能像 HTML 一样双击运行。复习时把保存的内容放回演练场对应文件；直到 Day12 才放进现有博客工程。
- 演练场打不开时，先向哥哥或 AI 报告访问问题，请其帮助提供同样的最小本地 Vue 练习环境；不把网络问题当成她学不会，也不花一天反复安装工具。

参考资料只查当天需要的条目：[Vue 中文交互教程](https://cn.vuejs.org/tutorial/)可选组合式 API；菜鸟教程用来查 HTML、CSS、JavaScript 的小例子，不必从头同时刷两套 Vue 课程。

### Day12～Day14：已有博客的本地修改

到时打开真正的博客文件夹，使用项目已有的 `npm run dev` 和 `npm run build`。不把前面的练习文件覆盖到博客入口中。

开始前按 Day12 指引保存当前文件副本、记录已有改动。遇到共享文件或改动归属不清时再找哥哥确认；其余可自行按步骤继续。只做本地修改和验证，不要求 push、发布，也不动部署配置。本轮交付的是任务文档，尚未替学生修改博客源码。

## 四、完整两周路线

这张表用于看方向，不是让她今天开始自学表中所有 API。前十二天的操作位置、示范和排错说明已写在对应任务中；Day13～Day14 待后续细化。

### 第一段：把已有静态卡片变成能操作的小页面

| 天 | 当天动作，按顺序做 | 新知识只限这些 | 交付物与小变式 |
|---|---|---|---|
| [Day01](./Day01-让笔记卡片动起来.md) | 显示阅读状态 → 加按钮 → 找到元素 → 点击改变文字 | `id`、元素定位、`const`、命名函数、点击事件、`textContent` | 点“标记已读”变成“已阅读”；挑战：自己加“恢复未读” |
| [Day02](./Day02-让阅读次数增加与归零.md) | 显示数字 0 → 用变量保存次数 → 点击加一 → 增加归零按钮 | `let`、数字、赋值、加法，复用函数和事件 | 点击三次显示 3，归零显示 0；变式：每次加二 |
| [Day03](./Day03-用对象和数组整理笔记.md) | 把标题和摘要放进一个对象 → 放三条笔记进数组 → 读取第一条和总数 | 对象、属性、数组、下标、`length` | 页面显示第一条标题和总数 3；变式：加入第四条，总数变 4 |

**Day03 检查点：**用 Day02 文件解释点击处理函数并修改增加量；用 Day03 文件读取另一篇笔记和总数，分清下标与 `id`。两项都能完成或在少量提示后稳定完成，再进入 Vue；否则先补具体卡点，不按日历强行推进。

### 第二段：用 Vue 重做熟悉的需求

| 天 | 当天动作，按顺序做 | 新知识只限这些 | 交付物与小变式 |
|---|---|---|---|
| [Day04](./Day04-用Vue重做阅读计数器.md) | 用 Vue 显示次数 → 点击加一 → 归零 → 对比 Day02 | `<script setup>`、`ref`、插值、`@click` | 不手动改 DOM 也能更新数字；解释 `count.value` 和模板中的 `count` |
| [Day05](./Day05-控制笔记摘要的显示与隐藏.md) | 显示摘要 → 用布尔值决定显隐 → 点击切换 | `true/false`、取反 `!`、`v-if` | 摘要可展开、收起；变式：默认展开 |
| [Day06](./Day06-让数组生成笔记列表.md) | 放三条笔记数据 → 用同一份模板生成卡片 → 增加一条数据 | `v-for`、唯一且稳定的 `id`、`:key` | 三张卡片来自数组，而不是复制三份 HTML；新增数据后显示四张 |
| [Day07](./Day07-输入标题并做第一周复习.md) | 输入标题 → 旁边预览 → 清空 → 补做旧按钮或列表中的一个小动作 | `v-model`，其余是复习 | 输入变、预览变；清空显示为空；能重新做一个简单交互 |

**Day07 检查点：**按钮交互、布尔显隐、简单列表、输入绑定分项记录，分别看因果解释和实际修改。允许看自己的代码、查语法；未做过预测或变式的标“尚未验证”，不凭演示旧成果打勾。先按当天自查与 AI 单步提示推进，哥哥有空再从 [理解验收指南](./给哥哥-前七天理解验收指南.md) 选一题低频确认；有关键缺口就占用后面扩展时间补，不继续堆新 API。

从 Day04 开始，页面更新来自 Vue 对响应式数据变化的处理。不要把开发工具保存文件后的自动刷新或热更新，误当成 Vue 响应式原理。

### 第三段：组合成笔记列表，再修改博客

| 天 | 当天动作，按顺序做 | 新知识只限这些 | 交付物与小变式 |
|---|---|---|---|
| [Day08](./Day08-点击添加一篇笔记.md) | 输入标题 → 点击添加 → 给每条新笔记唯一 `id` → 拦截空白标题 | 条件判断、`trim`、`push` | 添加成功，输入框清空；空字符串和全空格不能添加；使用单调递增的编号，不用数组长度充当唯一编号 |
| [Day09](./Day09-按编号删除一篇笔记.md) | 点击某条的删除按钮 → 传入该条 `id` → 过滤掉它 | 函数参数、严格比较、`filter` | 删除中间一条不误删其他条，再添加也不出现重复编号 |

| Day13 | 测试边界情况 → 检查窄屏 → 运行已有构建命令 | 手动验证、读报错、必要的局部布局调整 | 记录空关键词、无结果、详情跳转、返回列表和窄屏结果，记录构建结果 |
| Day14 | 独立修改一个条件 → 演示自己写的功能 → 复盘求职表达 | 不加新知识 | 将“只搜标题”改成“标题或摘要”；讲清哪些是自己做的、哪些获得过帮助 |

Day09、Day10 提供缩减入口：新增删除还不稳，可用 Day06 的三篇成功版练最小删除或纯搜索；未做的集成测试单独记录。Day11 的组件扩展只拆展示内容，删除动作留在父组件，不强制学 emit。Day12 明确区分演练场的 ref 数组与博客导入的普通数组。

## 五、如果做不完，怎么取舍

**周期最多两周，功能范围可以缩小。**优先保留：按钮交互 → 数据列表 → 输入 → 搜索 → 在博客中验证。

1. 首先取消 Day11 的组件拆分和额外样式美化。
2. 再减少 Day08～Day09 的新增、删除；但数组、函数参数、比较、`filter` 的最小练习要保留，因为搜索需要它们。
3. 把腾出的时间用于前面的卡点。一次只重复一个小任务，不重新布置整章。
4. 到 Day12 仍不能理解搜索时，先在演练场巩固。回博客只选已掌握的局部修改，不让哥哥代写搜索充数。
5. 第 14 天照常实测：若搜索还不会，就测试已学会的点击交互和列表，如实列出剩余缺口。

| 记录 | 判断方式 | 下一步 |
|---|---|---|
| 独立完成 | 允许看自己的代码、查语法，不照搬当前题完整答案，能完成变式并解释 | 进入下一个小动作，隔天再抽一次 |
| 提示后完成 | 需要提示或同类小示范，之后能完成并解释 | 次日先做一个同类变式，再决定是否推进 |
| 仍未完成 | 有提示仍不知道怎么开始，或运行了却解释不了 | 继续拆小，先只找元素、只改文字或只改一个数据 |

看过示范后做成功是正常学习进展，不等于“假学”；只是需要再通过变式验证。卡住要记录具体位置，不用“没天赋”“态度差”代替排查。

## 六、哥哥怎么带：少陪写，多看小成果

### 第一天

只帮她确认文件保存、浏览器打开、控制台能看到。不要顺手把按钮逻辑写完，也不要临时追加“顺便理解闭包”之类的要求。

### 平时文字沟通，不要求每天交录像

她本地保存代码与一条测试记录，给哥哥发三句即可：

```text
今天做到 Day__ 第__步，我实际改了______。
我原先预测______，运行后______，依据是代码里的______。
还卡在______，试过______，下一步准备______。
```

需要排错或抽查时，再补代码、可复现链接、截图或一分钟内演示。截图只能说明某次画面，不能单独证明理解；没有截图也不能据此断定没动手。因果解释可以用自己的话或箭头，不考口才，不用长篇学习报告。

### 有空再低频抽一题，约 5～15 分钟

具体问题、参考判断和补练见 [给哥哥：前七天理解验收指南](./给哥哥-前七天理解验收指南.md)。因果理解与写法熟练度分开记录，不要求闭卷默写，也不只听术语定义。

- 先让她展示，再提一个小变化，如“加一改加二”“默认收起改展开”“标题搜索加上摘要”。
- 给思考和查语法的时间，不要求秒答术语。
- 只追问：动作从哪里开始？哪个值或元素变化了？怎样证明结果是对的？
- 每次只指出最优先的一个卡点。反馈具体行为，例如“你这次自己发现了两个 `id` 不一致”。
- 可以文字异步问，不强制每隔几天在线。哥哥没空时保留尚未确认的状态，不因此停下所有练习。
- AI 使用率低只能说明工具用得少，不能单独判断学习投入或意愿；订阅用了多少天，也不能用来推算训练进行了多少天。

### 白天卡住时的 AI 求助模板

```text
我是只能独立写静态卡片的前端初学者，正在完成 Day__ 的第__步。
我想要的效果：______
现在实际看到的：______
我尝试过：______
第一条报错（没有就写没有）：______
当前相关代码：______

请先检查我卡在哪，不要替我改文件或生成整页答案。
一次只给一个提示，让我自己操作后再继续。
如果缺基础，给一个更小的同类例子，不直接完成当前题。
最后给一个只改变一个条件的练习，确认我能自己做。
请区分“照示范完成”和“独立完成”，不要因为运行成功就直接宣布我掌握了。
```

把 AI 当随时能问的老师，但答案也要运行验证。哥哥负责低频抽查，不承担全天实时客服。

## 七、求职与练习并行

- 前几天同步核实学籍、毕业证类型、预计毕业时间和可实习时长。五年制不能只按年数判断学历，也不照背旧文档的“中专”口径。
- 收集匹配的真实岗位要求、学校就业渠道和实习机会，不等教程全部刷完才了解招聘。
- 有能独立演示和修改的小功能后，可以开始针对性投递并记录反馈；这不保证录用，未掌握的能力要如实说明。
- 简历只写自己确实完成且能解释的内容，区分初版 AI 辅助搭建和自己的后续修改，未独立完成的部分不写“从零独立开发”。
- 接口请求、加载与错误状态等仍是本轮缺口。根据岗位需求和实测表现决定后续优先级，不临时全部塞进这两周。
- 不因赶时间接受培训贷、先付费才能入职等条件。

## 八、下一次怎么继续

按上方 Day01～Day12 的入口逐步练，每天先做前置检查，不用一次读完全部文档，也不把提前生成文档当作学生已完成。

接下来细化 Day13～Day14 时，带上实际代码、卡住的步骤、Day11 分项记录，以及 Day12 搜索、详情往返和构建是否做过的真实结果。哥哥没来得及抽查的项目如实标注即可。
- 数组、输入、筛选关系能解释，也能改一个小条件验证：继续在博客做边界测试和同类规则变式。
- 因果清楚、只是语法不熟：可以带自己的代码和语法小抄，不以默写作为推进门槛。
- 有方向但需要提示：下一次先补一个同类小动作，再决定是否推进。
- 关键关系仍断开：只补对应动作，缩减后续扩展，不延长两周上限，也不让 AI 代写作业。
