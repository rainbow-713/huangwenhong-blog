## 第 3 步：先用纸推演 filter，不急着粘代码（约 15 分钟）

现在的目标不是“找出要删的并留下”，而是“留下所有不该删的”。

`filter` 遍历数组，对每项执行你给的判断函数：返回 `true` 就保留在结果数组中，返回 `false` 就不放进去。原数组不会仅因调用 filter 就缩短；它返回的是一个新的数组。

假设要删除编号 203，填表：

| 当前 `note.id` | 目标 `id` | `note.id !== id` | 结果数组是否保留 |
|---|---|---|---|
| 101 | 203 | true | 保留 |
| 203 | 203 | false | 不保留 |
| 305 | 203 | true | 保留 |

- `!==`：严格不相等，类型或值不同就不相等。
- 本例的编号都是数字，目标也来自对象中的数字，不要手工给参数加引号。
- `203 !== '203'` 是 true，因为类型不同；今天不通过输入框收删除编号，所以无需新增类型转换功能。
- 若用 `===`，留下的是目标那篇，其他篇反而被筛掉。

**两分钟诊断：**把目标换为 101，不运行，先说三行的真假和剩余编号。能说“只剩 203、305”并解释为什么，就是在理解保留规则；只背“filter 是过滤”还不够。

## 第 4 步：把筛选结果作为新的完整列表（约 20 分钟）

**打开哪里：**用下面函数替换刚才只含 console 的整个 `removeNote`，不新增第二份同名函数。

```js
function removeNote(id) {
  notes.value = notes.value.filter(function (note) {
    return note.id !== id;
  });
}
```

从右往左读赋值：
1. `notes.value.filter(...)` 取出当前完整数组，逐项判断。
2. `function (note) { ... }` 是交给 filter 的判断函数；filter 每检查一篇，就把那篇交给参数 `note`。不用你手动调用三次。
3. 判断函数内的 `return` 把 true 或 false 返回给 filter，不是结束外层的整个 `removeNote`。
4. filter 把保留项组成结果数组。
5. 左边 `notes.value = ...` 把结果放回，之后 notes 才变短。
6. Vue 按 `v-for` 和总数的依赖更新页面。

这里两处 `note` 的用途相似但属于不同位置：模板循环中的临时当前项，和 filter 判断函数中的参数，各自在自己的范围里使用；不要把参数写到函数外。

**先预测再点：**从初始三篇开始，点 203 的按钮；应剩 101、305，总数 2。

**如果不对：**
- 点击有日志但没删除：是否仍在运行旧函数？
- 算出了结果但列表不动：是否漏掉左边 `notes.value =`？
- 一次全部消失：判断函数是否漏了 `return`？没有返回 true，项就不会保留。
- 只剩被点击那篇：是否把 `!==` 写成 `===`？
- `filter is not a function`：notes 里是否已经被错误的 push 赋值变成数字？回看 Day08，不盲改 filter。

**对比昨天：**push 直接改变数组，不接它的返回长度；filter 返回新数组，要在“删除”动作里把新数组赋回。这不是两种写法任选其一。
