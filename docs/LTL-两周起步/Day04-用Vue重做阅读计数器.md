## 第 2 步：准备一个 Vue 能跟踪的次数（约 10 分钟）

**打开哪里：**`<script setup>` 内，用下面两行替换提示注释。

```js
import { ref } from 'vue';

const count = ref(0);
```

今天先这样理解：
- `import`：从 Vue 取来 `ref` 这个工具，不是下载到页面的数据。
- `ref(0)`：创建一个 Vue 能跟踪变化的数据容器，里面最开始是数字 0。
- 在脚本里，`count.value` 读写容器里的数字。
- `const count` 不允许把变量重新指向别的东西，但可以修改这个容器的 `.value`。它和 Day02 的 `let count = 0` 不是同一种存放方式。

**做对时看到：**画面仍是 0。这时模板还写着固定的 0，不能仅凭画面相同认定已绑定。

**没对上，先检查：**是否漏了导入；是否写成 `ref('0')`；是否在原脚本外又加了一对脚本标签。

## 第 3 步：让显示位置读取次数（约 15 分钟）

**打开哪里：**`<template>` 内原来的 `<p>阅读次数：0</p>`。

**只替换这一行：**

```html
<p>阅读次数：{{ count }}</p>
```

`{{ count }}` 是插值：这里显示数据的值，不是固定的文字 `count`。

**做一个可观察的小实验：**
1. 先预测：把脚本的 `ref(0)` 改为 `ref(5)`，新实例最开始显示什么？
2. 修改，等待演练场重新编译；应看到 5。
3. 改回 `ref(0)`，确认回到 0。

**没对上，先检查：**是否仍写死为 0；花括号是否是两对英文括号；是否把 `count` 拼错。

这里 `count` 是脚本顶层的 ref，模板会自动取它的值，所以模板写 `count`，脚本写 `count.value`。先记当前例子的边界，不推导“所有位置的 ref 都不用 `.value`”。

刚才修改源码触发了演练场重新编译；这还不是“点击时 Vue 自动更新页面”的证据。接下来保持代码不变，用按钮验证。

## 第 4 步：写加一动作，再连接按钮（约 15 分钟）

### 4.1 在脚本里新增动作（约 10 分钟）

**打开哪里：**`const count = ref(0);` 后、`</script>` 前。

```js
function addRead() {
  count.value = count.value + 1;
}
```

右边先读旧值并加一，左边把新值存回容器。这里没有手动更新 DOM 的第二行。

**做对时看到：**预览仍从 0 开始，按钮还不会加一，因为尚未连接。

**没对上，先检查：**是否把 `ref(0)` 放进函数里；左右是否都有 `.value`；英文括号是否完整。

### 4.2 修改原按钮，不再加一个按钮（约 5 分钟）

**打开哪里：**模板内原来的“阅读一次”按钮，整行替换为：

```html
<button type="button" @click="addRead">阅读一次</button>
```

`@click` 是 Vue 模板中的点击绑定，这里表示“点击时执行这个动作”。

**做对时看到：**不再编辑代码、不刷新，连点三次得到 0 → 1 → 2 → 3。

**没对上，先检查：**是否少了 `@`；函数名大小写是否一致；模板是否仍是固定的 0；脚本是否误写 `count = count + 1`。

注意区别：原生 `addEventListener('click', addRead)` 传函数；Vue 的 `@click="addRead"` 也可写成 `@click="addRead()"`，后者在事件发生时执行，不会因为带括号就自动在加载时执行。今天统一用前一种，不照搬 Day02 对括号的排错结论。

## 第 5 步：做一个归零按钮（约 15 分钟）

**打开哪里：**脚本末尾，保留加一函数。在它的 `}` 后新增：

```js
function resetRead() {
  count.value = 0;
}
```

再到模板里，在原按钮后、`</main>` 前新增：

```html
<button type="button" @click="resetRead">归零</button>
```

**做对时看到：**加三次显示 3 → 归零显示 0 → 再加一次显示 1；重复归零仍为 0。

**没对上，先检查：**归零函数是否改的是同一个 `count.value`；两个按钮是否误绑了同一个函数；新函数是否错误放进加一函数里。

这一次只改数据，Vue 会根据模板关系更新显示。更新由 Vue 调度，不是要求你证明每行 JavaScript 后 DOM 都已经同步变化；今天只看一次操作完成后的画面，不学 `nextTick`。

## 第 6 步：对照 Day02，说出变化在哪里（约 10 分钟）

允许把两个文件同时放在眼前，不需要背下表。

| 问题 | Day02 原生 JavaScript | 今天 Vue |
|---|---|---|
| 次数放哪里 | `let count = 0` | `const count = ref(0)`，脚本读写 `.value` |
| 谁连接点击 | `addEventListener` | 模板中的 `@click` |
| 页面显示从哪里来 | 自己赋值 `textContent` | 模板插值读取次数 |
| 次数变了后 | 自己再写一行更新文字 | Vue 跟踪数据变化，更新对应画面 |

指着自己的代码说一遍：

```text
点击按钮 → addRead 执行 → count.value 加一
→ Vue 根据 {{ count }} 的关系更新次数显示
```

**做对的标准：**能指出这条链，而不只是说“Vue 很方便”“这是响应式”。不用讲 Proxy、依赖收集或虚拟 DOM 源码。

如果只能念术语，先问自己：“若模板写死 0，点按钮还能看到增加吗？为什么？”预测后可以在成功备份的副本里试，验证后恢复插值。

## 常见问题与最小排查

| 现象 | 先检查 |
|---|---|
| `ref is not defined` | 脚本是否导入了 `ref` |
| `Assignment to constant variable` | 是否对 `count` 本身重新赋值，应改 `count.value` |
| 一直是 1 | 是否写成固定赋值，或函数里重新创建次数 |
| 数字出现拼接或异常文字 | 初值是否数字，计算是否正确使用 `.value` |
| 点击没变化 | `@click` 名字、插值、第一条报错，逐个检查 |
| 模板中的 `.value` 报错或空白 | 当前顶层 ref 在模板里直接用 `count` |
| 有多个脚本或重复声明 | “新增”只加一次，起始骨架仅替换演练场练习文件 |
| 刷新后次数没保留 | 没做持久化，新实例从源码初值开始 |

卡住时用本页开头的 AI 求助语句，附当前代码、预期与实际结果；一次只检查一处。
