## 第 2 步：准备一份字符串数据（约 10 分钟）

**打开哪里：**脚本内，替换提示注释：

```js
import { ref } from 'vue';

const title = ref('');
```

- `''` 是空字符串，两个英文引号之间没有文字，也没有空格。
- `title.value` 是脚本中读写的标题文本。
- `placeholder` 只是输入为空时的提示，不是 `title` 的默认值。

**做对时看到：**页面还没有新的变化；输入框里的字不会因为这两行就自动进入数据。

**没对上，先检查：**引号是否成对；是否把空字符串误写为未定义的变量；`ref` 是否导入。

## 第 3 步：让预览读取标题（约 10 分钟）

**打开哪里：**模板中的预览段落，整行替换：

```html
<p>预览：【{{ title }}】</p>
```

**做对时看到：**预览为 `预览：【】`。输入框即使输入文字，预览也暂时不跟随，因为还没绑定输入。

**没对上，先检查：**插值是否拼对；是否误把 `title` 写成固定文字；当前预览是否因代码重编译刚被重置。

先问自己：“现在模板能读数据，但输入框知道该把字存到哪里吗？”下一步只补这个联系。

## 第 4 步：让输入框与标题数据连接（约 10 分钟）

**打开哪里：**模板里的输入框，整行替换为：

```html
<input id="note-title" v-model="title" type="text" placeholder="输入一个标题">
```

本例的 `v-model="title"` 建立两个方向：
- 用户在输入框输入 → 标题数据更新。
- 标题数据改变 → 输入框显示也更新。

预览的变化来自另一个关系：`{{ title }}` 也在读取同一份数据。不是输入框直接“把字复制到 p 标签”。

**做对时看到：**在预览区域输入“我的笔记”，完成输入后，预览为 `预览：【我的笔记】`；删除最后两个字，预览随之缩短。

**没对上，先检查：**是否写成 `v-model="title.value"`（本例模板直接用顶层 `title`）；输入框和插值是否使用同一个变量。

**中文输入提醒：**拼音输入法还在选候选词的组合输入阶段，预览可能暂时不更新；选词确认后再检查。不要把输入法尚未提交当成绑定失效。今天不加 `.lazy`、`.trim` 等修饰符。

## 第 5 步：用一个动作让两处一起清空（约 15 分钟）

**打开哪里：**脚本中 `const title = ref('');` 后、`</script>` 前新增：

```js
function clearTitle() {
  title.value = '';
}
```

再在模板的预览段落后、`</main>` 前新增：

```html
<button type="button" @click="clearTitle">清空</button>
```

**操作：**先输入“练习 Vue”，确认预览出现，再点击清空。

**做对时看到：**输入框为空，预览为 `预览：【】`。输入框重新出现 placeholder 属于提示文字，不是数据又变成“输入一个标题”。

**没对上，先检查：**按钮函数名；脚本是否改同一个 `title.value`；是否误写 `title.value = ' '`，那是一个空格，不是空字符串。

指代码解释：

```text
键盘输入 → v-model 更新 title → 插值更新预览
点击清空 → clearTitle 修改 title.value
→ v-model 让输入框变空，插值让预览变空
```

两个方向都验证过，才比只说“双向绑定”更能说明理解。

## 第 6 步：只看输入与数据，不急着加功能（约 10 分钟）

依次检查，不改源代码。先遮住预期列写自己的预测，再操作，把真实结果记到 `完成记录.md`；没提前预测就如实写“当时未预测”：

| 操作 | 预期 |
|---|---|
| 输入英文 `Vue` | 预览为 `预览：【Vue】` |
| 输入中文并确认候选词 | 预览显示确认后的中文 |
| 在输入框全选并删除 | 预览为 `预览：【】` |
| 输入一段文字后点击清空 | 输入框和预览都空 |
| 连点两次清空 | 仍为空，无报错 |
| 输入前后带空格的 ` Vue ` | 数据保留空格，今天没有自动去空格 |

最后一项不要只凭肉眼判断空格数量：HTML 文本显示可能折叠连续空白。今天只需知道没有使用去空格处理，不把“看起来空白”当成 `''` 的证明；不为此增加字符串长度或校验功能。

不用手动操作 DOM，不把预览写死为“周末练习”。挑战未完成时保留尝试与成功版，不让 AI 直接补成品。

## 第 8 步：从旧功能中选一个来复习（约 15 分钟）

**先保存今天：**已做输入练习，就将当前版本保存到 `practice/day07/App.vue`，确认文件有完整脚本、模板、样式，做通时保留清空版。若今天只补旧题，先保留当前源码，不为此新建空输入文件。下面会临时切换练习，不能直接覆盖尚未保存的内容。

根据自己的记录选最不清楚的一项，只做一项，不整页默写。旧源码仍从 `前端练习/day04`、`day05` 或 `day06` 取；只在演练场修改副本，今天的结果交到 `practice/day07`，不覆盖原文件。不要求先补交旧天数。

如果第 7 步已经做了小变式，而首次 Git 准备占用了复习时间，本步可以标“待补：具体哪一项”，留给 Day08 开头；不把没做写成通过。

| 复习方向 | 怎么操作 | 验证什么 |
|---|---|---|
| 按钮与数据 | 将 Day04 成功文件放回演练场，只清空加一函数的大括号内部，再自己补动作 | 知道修改哪个值，三次点击、归零后再加正确 |
| 布尔开关 | 将 Day05 成功文件放回演练场，只清空切换函数内部，再自己补动作 | 不是固定设为真，能连续切换两次 |
| 列表与当前项 | 将 Day06 成功文件放回演练场，只把卡片标题插值改为“待补标题”，再自己恢复读取当前项 | 每篇显示自己的标题，不全读第一篇 |

可以看此前自己的代码和官方语法说明，允许编辑器补全。知道该改哪里但拼写忘了，就先口述步骤，再查写法；不要求不用任何参考。

**保存与恢复：**把复习结果另存为 `practice/day07/复习-Day04.vue`、`复习-Day05.vue` 或 `复习-Day06.vue`，不要覆盖之前成功文件。已做输入练习的人，复习后将 `practice/day07/App.vue` 恢复到演练场，复查输入与清空；只补旧题的人记录“输入尚未开始”，不假装两项都做过。

**做对的标准：**能先说出准备做的改动，再用结果验证。看过答案后补成功也算学习进展，但记“示范后完成”，下次换小条件再验证。

## 第 9 步：第一周记录与首次提交（约 25～30 分钟）

这不是“前七天全部掌握”的认证，逐项如实记录：

| 能力 | 本次状态 | 具体证据或卡点 |
|---|---|---|
| 按钮改变数据 |  | 选用哪个旧练习，改了什么 |
| 布尔值控制显示 |  | 能否预测连续两次点击 |
| 数组生成列表 |  | 能否说明数量、当前项与编号 |
| 输入和预览 |  | 输入方向、按钮修改数据方向是否都验证 |

本次状态可写“独立完成／提示后完成／示范后完成／仍未完成／尚未验证”。这里“独立完成”允许看自己的代码和查语法，不代表能从零默写。仅演示过旧成果但没做解释或小变式的项目，写“尚未验证”，不直接打勾；没测的旧能力不必为了填表重新测一遍。

今天交付的文件：
1. `practice/day07/App.vue`：当前输入练习；`App-清空成功.vue` 只在确实跑通后保留。
2. 实际做过的 `App-填入标题.vue` 或一份复习文件，例如 `practice/day07/复习-Day06.vue`。注明哪个是尝试、哪个已跑通；没做就不建空文件。
3. `practice/day07/完成记录.md`：按 [记录模板](./README.md#homework-record)写日期、一次输入后清空的实际验证、帮助与卡点，并放入上面的分项表和下面三句。不要求全部能力都有证据；代码提示和 Git 操作帮助分开写，别人帮你建分支不等于别人替你完成输入功能。
4. 可选分享链接：说明链接对应输入练习还是复习文件，不拿一个链接冒充两个版本。

```text
输入框和预览共同使用______；按钮改它后，两处______。
我复习了______，原来卡在______，现在通过______验证。
下次最需要补______；本次用了______提示或资料。
```

分享链接按 [源码保存方法](#source-save)作为补充。重新打开源码，新实例仍从 `ref('')` 开始；没有保存运行时输入，不把它误当笔记保存功能。

<a id="first-push"></a>

### 9.1 检查今天真正要交什么

第一次不要直接点击 VS Code 的“全部提交／同步更改”。先把演练场最新内容保存到对应文件，在博客根目录的 PowerShell 一条条执行；失败就停，不把后面的命令一起粘贴：

```powershell
git branch --show-current
git status --short
git diff --cached --stat
```

- 分支必须是 `ltl-practice`；仍在 `main` 就不要继续，先回 [第 0 步](#practice-setup)处理，保留已有内容。
- 首次新建目录时，状态可能只显示 `?? practice/`，意思是有未跟踪文件，不是上传失败。先在 VS Code 展开目录，确认里面只有实际作业，没有密码、个人资料或无关文件。
- 第三条命令此时应无输出，表示还没暂存。已有不明暂存内容先确认归属，不混着提交。
- 做了输入练习就打开 `App.vue`，确认不是误存成复习版；只补旧题则检查实际的复习文件，不新建空输入文件。打开 `完成记录.md`，确认不是未填写的模板，也不是把任务预期抄成自己的结果。

### 9.2 只暂存 Day07，再看差异

```powershell
git add -- practice/day07
```

`add` 是把这次要交的文件放入暂存区，还没有传给哥哥。不要用 `git add .`。然后查看：

```powershell
git diff --cached --stat
git diff --cached
```

第一条看文件清单，第二条看具体内容；进入分页界面时按 `q` 退出，也可在 VS Code“暂存的更改”逐个看。应只出现 `practice/day07` 下自己的源码、记录、实际备份或尝试。

首次提交新文件时，整份文件都是新增很正常，不是只交你手敲的几行。但必须知道哪些来自骨架、哪些自己写或参考过示范。若出现 `src`、`docs`、锁文件等，先停下核对；不要一边不确定一边提交。

若暂存后又修改了文件，先 Ctrl+S，再重新执行本步的精确暂存和差异检查，否则 commit 可能只保存修改前的版本。

### 9.3 创建本地提交

确认差异后执行：

```powershell
git commit -m "chore(practice): 提交 Day07 输入与复习进展"
```

这条消息表示交进展，不要求所有功能已完成。只做了输入或补练旧题，可以把消息文字改成真实内容；不要写“前七天全部掌握”。

成功时通常会显示分支名、短提交编号和文件变化数量。`nothing to commit` 表示没有新的已暂存改动，不能当成本次新提交成功：检查是否未保存、未暂存，或之前已经提交，不制造空提交。身份或其他报错用 [Git 求助模板](./README.md#homework-help)处理，不冒用哥哥身份。

`commit` 只在自己电脑记录版本。此时还要推送，不能告诉哥哥已经交到了远程。

### 9.4 推送到练习分支

提交成功后执行：

```powershell
git push -u origin ltl-practice
```

它把练习分支传到已确认的 `origin`；`-u` 记录这条分支的上游关系，不会把作业合并到 `main`。首次通常显示新分支信息；若显示 `Everything up-to-date`，可能之前已推过，仍需去网页核对版本。

遇到权限、网络、推送被拒绝等错误，保留源码和本地提交，标“已提交、待推送”，停下求助，不强推、不重新建仓库，也不重复创建同一份提交。

### 9.5 去仓库网页确认，再发链接

1. 在终端运行 `git log -1 --oneline`，记住刚才的短提交编号。
2. 浏览器打开已确认接收作业的 GitHub 或 Gitee 仓库，不是博客线上网站。
3. 找分支选择框，把 `main` 切到 `ltl-practice`。展开 `practice/day07`，打开源码和记录，确认最新内容都能看到。
4. 打开提交历史（Commits／提交），找到编号一致的本次提交，打开详情并复制浏览器地址栏链接。只发本地磁盘路径，哥哥无法在自己电脑访问。
5. 给哥哥发下面这段，空白按实际填写；未推送就报告待补交，不填假链接。

```text
Day07 第__步，完成 / 部分完成；提交链接：______。
输入与清空：实际做了______，结果______。
变式 / 复习：做了______，独立 / 提示后 / 示范后；待补______。
目前卡在______，我试过______；下次先做______。
```

**首次交付完成的标志：**远程练习分支里能打开当前源码和真实记录，提交编号对应，链接已发出。哥哥未查看仍是“已交付、尚未验收”，不等于已经掌握。

### 做了一部分，怎么交

| 当前情况 | 如实保存与交付 |
|---|---|
| 输入与清空做通，复习没做 | 交当前 `App.vue` 和记录；写待补哪一项，不新建空复习文件 |
| 第 4／5 步仍报错 | 交当前真实源码、第一条错误与尝试；没有成功就不命名成功备份 |
| 今天只补 Day06 列表 | 把今天实际改过的副本存为 `practice/day07/复习-Day06.vue`，记录来源和修改；不造输入版 `App.vue`，不补交整个 Day06 |
| 只完成环境检查，还没写代码 | 只交真实记录并注明尚无源码进展；不能算完成输入练习 |
| 分支或权限还没准备好 | 按第 0 步在仓库外保留源码与记录，发卡点，标待补交；解决后再正式回传 |

从 Day08 开始复用今天的分支，不每天新建。每次开工按 [任务同步](./README.md#homework-sync)，结束换成当天目录提交。哥哥有空再检查；待补的小练习放到次日开头，权限问题也需继续跟进。

## 排错与求助

| 现象 | 先检查 |
|---|---|
| 输入框能打字，预览不变 | 有没有 `v-model`；预览是否插值；是否同一个变量 |
| 预览显示字母 `title` | 是否把数据名当作固定文字 |
| 清空后输入框还有文字 | 输入框是否绑定到这份 title，函数是否正确赋值 |
| 清空后似乎还有空白 | 是否赋值成一个空格 `' '`，而非 `''` |
| 中文选择候选词时暂不更新 | 先提交组合输入再看，不急着改绑定 |
| 刷新后输入没了 | 当前没有持久化，初值为空正常 |

求助时使用本页开头的对应语句。若 AI 已经给出答案，记“示范后完成”，下一次换一个条件再检查。
