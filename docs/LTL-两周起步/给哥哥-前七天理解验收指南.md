# 给哥哥：前七天理解验收指南

> 目的：判断她有没有看懂“这段代码为什么产生这个结果”，不是考她能否默写。
> 范围：Day01～Day07 已练过的小功能。允许看自己的代码、用编辑器补全、查语法；不要求框架源码、专业术语背诵或从空白重写整页。

## 你今晚就可以怎么做

只选她最近做过的一天，打开她自己的成功文件，花约 10～15 分钟：

1. **先预测：**不改代码，问“我这样操作两次，页面会怎样？为什么？”
2. **再指位置：**让她指出“从哪触发、改哪个数据、哪个画面使用它”。
3. **改一个条件：**换个增加量、初始值或标题，不额外塞新知识；先说准备改哪里再操作。
4. **用结果验证：**实际运行。若与预测不同，请她找最先对不上的一步，再修正解释。

**本次有理解证据 = 能对照具体代码解释因果，并在一个小变化里验证解释。**不等于永远掌握，也不意味着已经具备岗位全部能力。隔一两天换一个同类小条件再看。

下面每个 Day 都有你可以照着问的问题、你应听到的意思、卡住后的提示。参考说明是给你的判断依据，不要先发给她背，再考同一道题。

## 一、哪些算理解，哪些还不能下结论

### 不拿这些作为单独的通过标准

- 能跑出与教程一样的页面。
- 把 `ref`、响应式、双向绑定、key 的定义背得很顺。
- 能照着抄、能说“这个就是这样写的”。
- 手敲快、代码行数多、坐了很久。
- 你说出该改哪一行，她改完后点头说懂了。

它们不是坏事，只是还不足以证明因果理解。继续用一项小预测或小变化验证，不贴“假学”“没天赋”标签。

### 四个观察维度，分开记，不凑总分

| 维度 | 怎么看 | 足够的表现 |
|---|---|---|
| 预测 | 运行前说两次操作的结果 | 不仅报数字，还能说明旧值如何变新值；错了能沿代码修正 |
| 解释 | 指着自己的代码走一遍 | 能连接触发、数据和显示，不只是念 API 名 |
| 修改 | 换一个已学范围内的条件 | 知道改哪类位置；语法可查，允许你协助输入但需记录 |
| 验证 | 运行后核对预测 | 会看重复操作、归零后再做等结果，不只看一次“好像行了” |

**理解和独立实现分别记录：**
- “能解释为什么，但 `.value` 忘了写，查资料后修好”：有因果理解证据，写法还不熟。
- “能照样改成加三，却不知道下一次为什么是 6”：实现了一个结果，理解仍待验证。
- “语言表达慢，但能指着代码、画箭头、写出值变化”：同样有效，不考口才。
- 只看过截图、只演示旧代码：记录“运行成功／尚未验证理解”，不猜独立性。

## 二、一次十五分钟的具体话术

| 时间 | 你怎么说 | 你观察什么 |
|---|---|---|
| 0～2 分钟 | “打开你昨天成功的文件，先演示一下。” | 文件是否是她的版本，基础功能是否可复现 |
| 2～5 分钟 | “先别点。按这个顺序操作，最后是什么？指代码告诉我原因。” | 是否真在推演，而不是说以前见过的结果 |
| 5～10 分钟 | “只换这一个要求。你准备改哪里？可以看代码和查语法。” | 是否定位数据、函数、模板，不随机试所有数字 |
| 10～13 分钟 | “现在验证。哪里与预测一致？不一致最先出在哪？” | 能否把结果与代码对上 |
| 13～15 分钟 | “今天哪条关系清楚了？下次只补哪一个点？” | 留一项具体补练，不重新布置整章 |

时间是控制你自己的抽查范围，不是倒计时施压。环境打不开先处理环境，不据此评判理解；连续几分钟明显卡住就进入提示或补练，别不停追问。

### 开头可以直接说

> “我不考你背代码，你可以看自己的文件。我们就确认这个按钮／数据为什么影响这里。先说预测，再指位置，最后改一个小地方试试。说错了也没关系，要看能不能找到原因。”

### 提示按层给，一次一句

1. **等她尝试：**先给约一分钟读代码和思考，不替她抢答。
2. **方向提示：**“这是初始值、点击动作，还是显示位置的问题？”
3. **范围提示：**“先只看这个函数／这个模板块，哪行使用旧值？”
4. **更小的同类例子：**用纸推演 1 加 2，或真取反；不直接写当前题答案。
5. 仍不明白就停止验收，转成教学。示范一个最小动作，隔天换条件再测。

给到第 2～4 层后做出来，记“提示后完成”。若直接看完整解答做出来，记“示范后完成，理解待验证”。不要事后把这些都填成独立完成。

正常学习可以问 AI；为了观察她当前的判断，验收时先让她自己解释，AI 只查具体语法或给单步提示，不生成当前题的完整回答。用了什么帮助如实记录即可。

## 三、先判断卡在哪一层，不按日历判断水平

这是本轮训练的观察地图，不是对人贴等级；同一个人可能在不同功能上处于不同位置。

| 层次 | 可观察动作 | 相比前一步多了什么 | 2～5 分钟诊断 |
|---|---|---|---|
| 1. 分清静态显示与运行变化 | 指出哪段写死，哪段由脚本改变 | 不再把所有页面变化都当成“自动的” | Day01：只改静态初始文案，预测点击后是否仍被脚本覆盖 |
| 2. 接起事件与动作 | 指按钮、监听／绑定、函数、目标位置 | 知道动作从哪里开始 | Day01：暂不连接事件，函数存在会不会自己执行？ |
| 3. 追踪数据状态 | 列出旧值、新值、显示结果 | 不把页面文字当作数字变量 | Day02：加两次、归零、再加，解释两处都要重置 |
| 4. 读懂声明式关系 | 指 ref、模板插值或条件 | 知道 Vue 按模板与数据关系更新画面 | Day04／05：数据变了但模板写死，画面是否会跟着变？ |
| 5. 从一项推广到一组 | 指整组、当前项、每项编号 | 不再只会显示固定第一篇 | Day03／06：改第二篇，只应影响哪些地方？ |
| 6. 理解输入与数据双向联系 | 输入能改数据，按钮改数据也能改输入 | 能追踪两种起点走到同一份数据 | Day07：点清空为什么输入框和预览一起空？ |

### 前置关系怎么用

```text
静态页面与脚本位置 → 事件接动作 → 数字状态 → Vue 数据与模板关系
                                    ├→ Day05 布尔值和条件
                                    └→ Day07 输入绑定
Day03 对象／数组／属性 + Vue 模板关系 → Day06 列表
按钮／列表／输入分别清楚 → 后续组合成新增、删除、搜索
```

- 硬前提：读当前项之前要分清数组与对象；写 Vue 交互之前要知道数据与模板各在哪里。
- 软前提：Day05 的开关不是 Day06 列表的硬前提，Day06 列表也不是 Day07 输入的硬前提。某项卡住可以记录后单独补，不把所有后续任务机械封死。
- 本轮按顺序学方便管理，但未通过不等于“退回第一天重学所有内容”。只退到断开的那条关系。

## 四、Day01～Day07：你可以直接用的检查卡

每次选一张卡的“预测＋小改动”即可。故障题是可选项，一次最多一个，必须在副本中，并提前说“我刻意改了一处，我们一起找”，不用偷偷破坏她的成果。

各题独立从当天的标准成功版开始，不叠加前一道变式：例如 Day02 故障题先恢复每次加一，Day05 恢复默认收起。变式结束先恢复原版，再验证原功能；若她的命名、内容不同，按实际代码调整提问，不要求为了验收改成教程一模一样。

### Day01：按钮为什么能改文字

对应 [Day01 任务](./Day01-让笔记卡片动起来.md)。

**直接问：**
> “刚打开是什么？点‘标记已读’后是什么？如果只把 HTML 中的初始文字改成‘还没开始’，点击后会不会一直保留这四个字？请指出原因。”

**你应听到的意思：**初始由 HTML 给出；点击后监听调用函数，函数通过 `textContent` 覆盖目标位置，所以仍变为函数里设置的“已阅读”。能指出状态元素、按钮和函数的对应关系即可。

**小改动：**只把点击后的文案换为“本篇已看完”，先说应改函数里的赋值，不改初始 HTML；运行验证。

**理解还不清的信号：**反复改按钮的名字或 HTML 初始文字，解释不了为何点击后又变回旧文案；把“函数写在那里”当作它已经被点击调用。

**可选故障：**在副本中临时注释事件监听。函数仍存在，点击不再改字。请她定位哪条连接断了，而不是要求默写监听语法。

**提示／补练：**先让她把按钮、函数、目标文字画成三个框，再指出负责连线的代码。只补一个文案修改，不加第二个按钮。

### Day02：为什么归零不能只改显示

对应 [Day02 任务](./Day02-让阅读次数增加与归零.md)。

**直接问：**
> “现在每次加一。从 0 点两次、归零、再点一次，会显示什么？保存次数的变量和屏幕上的字是一回事吗？”

**参考判断：**2 → 0 → 1；`count` 保存数字，`countText` 指向元素。点击先计算再显示，归零也要重置数字并更新显示。她可以用自己的比喻，但必须能指到两行代码。

**小改动：**每次改为加三，初始仍为 0。两次点击应为 6，归零后再点为 3；不要求改函数名。

**可选故障：**归零函数只剩 `countText.textContent = 0;`。先加两次，再归零、再加；会显示 3，而不是 1，因为数据仍为 2。

**不够的回答：**“需要两行因为教程写了两行”；“页面是 0，所以变量肯定是 0”。

**提示／补练：**纸上画“程序数字”“页面文字”两列，逐行记旧值和新值；只练三次操作。不用补作用域、闭包等整章。

### Day03：对象、数组与下标为什么不同

对应 [Day03 任务](./Day03-用对象和数组整理笔记.md)。

**直接问：**
> “三篇数据里第二篇编号是 203。`notes[1].title` 分两步取的是什么？如果只把第二篇标题改掉，当前还显示第一篇的页面会变吗？总数会变吗？”

**参考判断：**先按位置取第二个对象，再取标题属性；显示第一篇时不受第二篇标题修改影响，总数仍为 3。`id` 是身份，不是数组下标。若她的最终作业是四篇，数量问题按实际数组调整，不强行期待 3。

**小改动：**让页面显示第三篇的标题和摘要，两处都要按下标 2 取值，总数不变。先确定数组确实至少有三篇，不故意越界。

**可选故障：**只把标题改成第三篇，摘要仍读第一篇。问“为什么标题和摘要对不上”，检查两处来源，不要求从头重写数组。

**不够的回答：**“`[1]` 是编号为 1”；“修改一篇标题会让数量加一”；只改控制台输出，以为页面也会变。

**提示／补练：**把三篇写成三张纸，标注位置 0、1、2 和编号 101、203、305，用手指出先取哪张、再取哪栏。

### Day04：Vue 为什么不用自己写 textContent

对应 [Day04 任务](./Day04-用Vue重做阅读计数器.md)。

**直接问：**
> “点按钮时没有写 `textContent`，画面为什么会变？请把按钮、函数、数字、模板这四处连起来。若模板写死为 0，Vue 会猜到这里也要更新吗？”

**参考判断：**`@click` 触发函数，函数改变 `count.value`，ref 的变化由 Vue 跟踪，模板 `{{ count }}` 使用它所以更新；固定的 0 不会被 Vue 猜成次数。这里不要求讲依赖收集源码。

**小改动：**只把初始次数改为 5，增加仍为 1，归零仍为 0。新实例先显示 5，点两次为 7，归零后为 0，不是自动回到 5。区分初值和重置函数的赋值。

**可选故障：**只把模板插值改成固定 0。数据照样变化，但画面不变；能指出模板没有读取数据即可。不要求她用开发工具查看内部状态证明所有细节。

**误解边界：**
- `const count = ref(0)` 不妨碍改 `.value`，它限制的是重新给 `count` 赋值。
- 在这些顶层 ref 例子里，脚本用 `.value`，模板自动取值；不推广成任意位置都自动解包。
- Vue 的 `@click="addRead()"` 也是事件发生时执行，不能拿原生 `addEventListener(..., addRead())` 的错误结论套它。
- 改源码导致重编译，不等于点击时的响应式更新；测试时停止编辑代码再点击。

**提示／补练：**把 Day02 的“自己改显示”与 Day04 的“模板读取数据”并排指一次，再做一个数字变式。

### Day05：是在切换，还是固定设成某个值

对应 [Day05 任务](./Day05-控制笔记摘要的显示与隐藏.md)。

**直接问：**
> “现在默认收起，连续点两次会怎样？如果只改成默认展开，两次又会怎样？请指出哪个是初值、哪个是每次点击的动作、条件放在哪个元素上。”

**参考判断：**`false → true → false`；改初值后是 `true → false → true`。函数根据旧布尔值取反，`v-if` 根据它决定是否渲染摘要；不是删除数据，也不应该把按钮一起移除。

**小改动：**保持默认值不变，把控制目标从摘要改成标题，摘要始终可见。只移动 `v-if` 到标题，预测标题与摘要各自变化后验证，再恢复。不要同时加按钮动态文字。

**可选故障：**把取反改为 `showSummary.value = true;`。第一次展开后，第二次还是展开；能说清“赋真”不等于“取反”即可。

**不够的回答：**“点两次总会切换”但不看函数；认为字符串 `'false'` 与布尔 `false` 相同；说 `v-if` 只是透明度。

**提示／补练：**用纸写 false／true，只推演两次赋值。再让她指出条件作用的那个标签，不追问 `v-show`、生命周期。

### Day06：三张卡片为什么内容各不相同

对应 [Day06 任务](./Day06-让数组生成笔记列表.md)。

**直接问：**
> “这里明明只写了一份 article，为什么有三张／四张？`notes` 和 `note` 各是谁？若只改第二篇标题，哪些东西变化，数量变不变？”

**参考判断：**`v-for` 针对数组每一项生成卡片；`note` 是当前这一项，所以属性各不相同；改一项标题不改数量。不要把“Vue 自动复制”当作完整解释，要指出数据来源和当前项。

**小改动：**先保存成功副本，只交换数组里前两个完整对象的位置，不改 id 或模板。预期卡片顺序交换，每篇标题和摘要仍配对，数量不变。

**key 只问到这一步：**
> “第一篇移到第二个位置，它的编号该不该改？`:key="note.id"` 用的是什么？”

足够的意思：位置变了，还是原笔记，编号不改；Vue 用这个唯一稳定标记对应前后的项。冒号让它取实际 id，而不是所有卡片都使用字面字符串 `note.id`。

不要说 key 会自动排序、去重，也不要要求“去掉 key 画面必须马上坏掉”。纯文本静态卡片不一定能展示错误复用的现象；本轮用身份推理验收，不背 diff 算法。

**可选故障：**把标题插值临时改为 `{{ notes[0].title }}`，摘要仍是 `{{ note.summary }}`。每张标题都读第一篇，摘要不同；问她究竟读的是哪条数据。

**提示／补练：**先只保留两篇，在纸上模拟第一轮和第二轮“当前 note”是谁，再恢复自己的数组。

### Day07：输入框与预览如何共用一份数据

对应 [Day07 任务](./Day07-输入标题并做第一周复习.md)。

**直接问：**
> “输入框打字后，字先到了哪里，预览怎么得到它？点清空时，为什么输入框和预览一起变空？placeholder 是不是保存的标题？”

**参考判断：**`v-model` 把输入同步到标题数据；插值读同一份标题。按钮把 `title.value` 设为空字符串后，绑定让输入框更新，插值让预览更新。placeholder 只是提示，不是数据。

**小改动：**只把初始标题改为“周一笔记”，保持清空函数不变。新实例的输入框和预览都有这段文字；手动改字仍同步；清空仍是空字符串，不是自动回到初始标题。

**可选故障：**副本中去掉输入框的 `v-model`，保留预览插值。输入框仍能打字，但数据没随输入变化，预览不跟随。请她解释“输入框本来能打字”和“数据绑定”不是同一件事。

**不够的回答：**只念“双向绑定”；直接改 p 标签完成预览，却不知数据是哪份；认为空格 `' '` 与 `''` 一样；以为预览即保存。

**验证注意：**中文输入先确认候选词，组合输入期间可能暂不更新。没有修饰符时不自动 trim；HTML 空白显示会折叠，不仅凭肉眼判断字符串。新实例从源码初值开始，不保留上次输入。

**提示／补练：**让她圈出标题数据的定义、输入绑定、预览插值、按钮赋值四处，分别画“输入 → 数据”和“按钮 → 数据 → 输入／预览”两条箭头。

## 五、一个完整示范：不会拼写，不等于没理解

场景：Day04，原本加一，希望改成加三。

1. 你：“先不运行，连点两次是什么？为什么？”
2. 她：“6。第一次把 0 加 3，第二次读到的是 3。”
3. 你：“要改哪一处？”
4. 她能指到函数中的加法，但写的时候忘了 `.value`。
5. 你先让她看报错或查 ref 语法，她自己修正；随后点两次、归零、再点，分别得到 6、0、3。
6. 记录：“旧值→新值的理解有证据；ref 写法尚需查；变式查语法后完成。”不用因忘记 `.value` 判整天失败。

另一种情况：她背出“响应式自动更新”，但问固定模板会怎样时不知道，也无法指出次数变量。记录“概念术语会说，数据到模板的关系待补”，回 Day04 对照两种模板，不继续追框架底层。

## 六、常见卡点与只补一个动作的办法

| 看见的卡点 | 可能断开的关系 | 下次只补什么 |
|---|---|---|
| 改 HTML，点击后又变回去 | 初始内容与运行时赋值未区分 | Day01 改初始字与点击后字各一次，逐次预测 |
| 归零看着成功，再加接着旧数 | 数据与显示混淆 | Day02 用两列记录归零前后，不写新功能 |
| ref 会背，但不知道模板为何变 | 数据来源与显示关系未连上 | Day04 固定 0 对照插值，各点一次 |
| 总把开关设为真 | 只记结果，没有用旧值推演 | Day05 纸上连续取反两次，再改函数 |
| 每张卡片全读第一篇 | 整组、固定项、当前项混淆 | Day06 两项数组模拟两轮，再用当前项显示 |
| 输入能打，预览不会动 | 原生输入行为与绑定混淆 | Day07 先圈数据，再连输入和预览 |
| 口头步骤对但总是漏符号 | 概念与语法熟练度不同 | 给语法小抄，修一处后换条件验证，不要求抄十遍 |
| 紧张说不完整 | 表达负担可能掩盖理解 | 让她画箭头或写值变化，不立即判不会 |

这里只是排查方向，不凭一次表现判断原因。先让她展示证据，再决定补哪一项。

## 七、前七天怎么安排低频抽查

不必每天陪学，也不在 Day07 一次把七张卡全问完：

- **日常异步：**看代码、一分钟演示、三句说明；重点记录她自己的预测和实际结果。只有视频不能证明完全独立，别过度推断。
- **Day03 附近一次约 15 分钟：**以 Day02 为主抽“数据和显示”；余下几分钟抽 Day03 的取值。Day01 事件连接作为自然追问，不加一套卷子。
- **Day05 附近一次约 15 分钟：**以 Day05 取反为主，顺带让她与 Day04 的数字变化作比较。
- **Day07 分两次各约 10～15 分钟：**第一次只看列表的当前项与编号；第二次看输入两个方向。两次之间可以隔一段休息或放到下一次，不必须同一晚。
- **隔一两天：**挑上次有提示的关系，换一个数或默认值再看；上次“提示后完成”有机会变成稳定独立，不永久贴标签。

### 判断下一步，不靠总分

- **因果清楚，变式能验证：**可以继续，语法不熟带小抄。
- **有方向，但需要一两次范围提示：**先记提示后完成，次日先补 5～10 分钟同类题，再推进。
- **代码运行了，仍无法指出数据和显示关系：**先不叠加依赖这项的新功能，安排一个最小补练。
- **某个并行能力卡住：**只卡住的项目补练，例如列表和输入分别记录，不能用另一项高分抵消，也不需要全盘重来。

两周上限不变，补练占用后续扩展项的时间，先砍组件拆分和美化，再减少新增／删除。不是延长每天学习时长去补进度。不要求所有边角 API 都掌握，但后续真正需要的按钮、数组、输入关系要有证据。

## 八、一分钟记录模板

复制到你自己的记录里，每次只写一个重点，不另写长报告：

```text
日期／练习：______，检查的关系：______
我的提问或小变化：______
她运行前预测：______；理由／指到的代码：______
实际结果：______；不一致后怎样定位：______
帮助：无 / 仅查语法 / 方向提示 / 范围提示 / 完整示范
理解证据：已有 / 提示后出现 / 暂无 / 尚未验证
实现状态：独立完成 / 提示后完成 / 仍未完成（示范后另注明）
下次只补：______；隔天复查用的新条件：______
```

最后反馈也说具体：
> “你今天能说明为什么归零要改数据，还用再次点击验证了。`.value` 还要查没关系。明天我们只换一个增加量，再看一次。”

不说“你已经全掌握了”，也不因一处拼写错说“你根本没学会”。看预测、代码和验证能否互相对应，这才是这一轮要建立的理解。
