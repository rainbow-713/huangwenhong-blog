## 第 4 步：认清这里的 notes 不是 ref（约 10 分钟）

看 NotesView 的导入：

```js
import { notes } from '../data/notes.js'
import NoteCard from '../components/NoteCard.vue'
```

再看 notes.js 的 `export const notes = [...]`，它导出的是普通数组，不是 `ref([...])`。

| 操作 | 演练场 Day10 | 博客今天 |
|---|---|---|
| 数据从哪里来 | 本组件 `ref([...])` | 从 JS 模块导入普通数组 |
| 脚本取数组 | `notes.value` | `notes` |
| 脚本筛选 | `notes.value.filter(...)` | `notes.filter(...)` |
| 输入关键词 | `keyword.value` | 仍然是 `keyword.value` |
| 模板访问结果 | `filteredNotes` | 仍然是 `filteredNotes` |

本轮把导入数组当只读来源。没有要求把它改成响应式数组，因为今天不在页面中新增、删除或原地修改这些数据。computed 会跟踪响应式 keyword；**普通导入数组不会仅因写进 computed 就自动变成响应式数据。**以后若有接口或运行时数据更新，是另一个任务。

`import { notes }` 表示拿到模块导出的绑定，不是从服务器请求笔记。今天没有网络搜索接口。

## 第 5 步：先在脚本增加搜索数据与规则（约 15 分钟）

**打开哪里：**NotesView 已有的 `<script setup>` 内。保留原来的两条导入，在它们前面新增：

```js
import { ref, computed } from 'vue'
```

如果当前版本已经导入其中某个工具，合并进同一条，不重复声明。

在所有导入之后、`</script>` 前新增：

```js
const keyword = ref('')

const filteredNotes = computed(function () {
  const word = keyword.value.trim()
  if (word === '') {
    return notes
  }
  return notes.filter(function (note) {
    return note.title.includes(word)
  })
})

function clearSearch() {
  keyword.value = ''
}
```

今天跟随项目现有无分号风格；有无分号不是此次学习重点，不格式化整仓库。

**与 Day10 相同的规则：**空词全显示、去两端空白、仅搜标题、区分英文大小写。不同之处只是完整数组的来源和脚本访问形式。

按 `Ctrl+S` 保存，等 Vite 更新。**此刻页面外观仍应原样**，因为模板还没有输入框，也没用 filteredNotes。

**没对上先查：**是否出现两份 `<script setup>`；有没有把脚本贴在模板里；是否误写 `notes.value.filter`；第一条错误是否说变量重复或找不到 computed。

## 第 6 步：在介绍文字后面加搜索区（约 15 分钟）

## 最常见的卡点，一次只查一处

| 现象 | 最先查什么 | 不要急着做什么 |
|---|---|---|
| 报 undefined 或读取 filter 失败 | 是否把普通 notes 写成 notes.value | 不修改 notes.js 来迎合错误写法 |
| 数字对了，卡片还是全部 | v-for 是否还在遍历 notes | 不把全部笔记从数据里删掉 |
| 输入能打字，但数字不动 | v-model、keyword 与 computed 是否同一变量 | 不添加第二套关键词变量 |
| 清空后找不回列表 | 是否曾覆盖、过滤赋回了原数据 | 不靠刷新掩盖问题 |
| 有卡片但标题、日期或链接坏了 | :note 是否仍传完整当前对象 | 不重写 NoteCard 或路由 |
| 英文小写搜不到大写 | 是否符合已约定的区分大小写规则 | 不把预期行为一律当故障 |
| 从详情返回关键词空了 | 列表组件是否重新创建、是否本来没做保存 | 不临时加持久化扩展 |
| 本地改了线上没变 | 是否打开的是本地 dev 地址 | 不为看变化直接发布 |
