# Day01：让笔记卡片动起来

> 今天只做一件事：点一下按钮，把笔记的“未阅读”变成“已阅读”。
> 你已经会写静态卡片，就从这里接着走。不学 Vue，不启动博客，不背防抖，不重写整页。

## 先看今天的终点

页面上有一张卡片：

```text
我的第一篇笔记
今天练习让按钮改变页面上的文字。
阅读状态：未阅读
[标记已读]
```

点击按钮后，只有状态变成“已阅读”。之后尝试自己再加一个“恢复未读”按钮。

**今天不追求漂亮，追求你能指出：哪个按钮，触发哪个动作，改了哪段文字。**

按约 2～3 小时安排，分段做。每个小步骤约 5～20 分钟，不是考试限时；第 3、6 步后各休息一下。若同一步卡住约 10～15 分钟，就用后面的求助模板，不一直硬耗。

| 做到哪里 | 今天要留下的结果 |
|---|---|
| 第 0～3 步 | 浏览器能打开卡片，有状态和按钮 |
| 第 4～6 步 | 找到元素，把点击和改文字连接起来 |
| 第 7 步 | 自己改文案并检查结果 |
| 第 8～9 步 | 做一个独立变式，讲清楚，保存交作业 |

**使用约定：**HTML/CSS 起始骨架可以复制；新学的 JavaScript 小段自己输入并运行。示范中写“新增”的只加一次，写“替换”的不要把新旧两份都留下。代码框外的解释不用输入。

## 第 0 步：给今天的练习找一个位置（约 10 分钟）

**打开哪里：**Windows 桌面、文件资源管理器和 VS Code。

**只做这些动作：**

1. 在桌面空白处右键 → 新建 → 文件夹，命名为 `前端练习`。
2. 打开它，再新建一个文件夹，命名为 `day01`。
3. 打开 VS Code，选择“文件 → 打开文件夹”，选刚建的 `day01`。
4. 在 VS Code 左侧文件区域点击“新建文件”，输入文件名 `index.html`，回车。
5. 先输入下面两行，按 `Ctrl+S` 保存。第一行让浏览器按 UTF-8 读取中文：

```html
<meta charset="UTF-8">
<h1>今天开始动手</h1>
```

6. 用资源管理器进入 `前端练习/day01`，双击 `index.html`。若打开的是编辑器，右键 → 打开方式 → 选择 Edge 或 Chrome。

**做对时看到：**浏览器页面上有“今天开始动手”。地址通常以 `file:///` 开头，末尾是 `day01/index.html`，不是原来博客的网址。

**没看到，先检查：**
- 文件名必须是 `index.html`，不能是 `index.html.txt`。资源管理器“查看 → 显示 → 文件扩展名”可显示真实后缀；菜单位置不同时找“文件扩展名”。
- VS Code 要先 `Ctrl+S` 保存。浏览器看的是硬盘里已保存的文件。
- 网页上出现代码而不是标题时，先检查扩展名和“打开方式”。
- 不知道是否开对文件：关闭这个练习的浏览器标签，再从 `day01` 文件夹重新打开。

今天不要打开或覆盖博客里的同名 `index.html`，也不用敲任何 npm 命令。如果这一步超过 10～15 分钟仍卡住，先请哥哥帮你确认文件位置，不用重新安装环境。

## 第 1 步：放上一张你能看懂的静态卡片（约 10 分钟）

**打开哪里：**VS Code 的 `day01/index.html`。

**只做这些动作：**

把刚才两行临时内容全部替换为下面的起始骨架。这一份可以复制，不用默写 CSS。已经有自己的卡片也可以用，但要能找到卡片的结束位置。

<head>

1. 保存；切到浏览器，按 `Ctrl+R` 刷新。
2. 回 VS Code，把 `<h1>` 中的标题改成你自己的标题，其他部分不动。

**做对时看到：**一张白色卡片，里面的标题是你刚改的。

**没看到，先检查：**是否保存；浏览器是否刷新；是不是改了另一个 `index.html`。

这里的变化来自“修改文件 → 保存 → 浏览器重新读取”。**它不是按钮交互，也不是 Vue 响应式。**

## 第 2 步：加状态和按钮，但先不写动作（约 10 分钟）

**打开哪里：**同一个 `index.html` 的 `<article class="card">` 里面。

**只做这个动作：**找到摘要那一行，在它后面、`</article>` 前面，新增下面两行，不替换原来的标题和摘要。

```html
<p>阅读状态：<span aria-live="polite">未阅读</span></p>
<button type="button">标记已读</button>
```

保存、刷新，然后点一下按钮。

**做对时看到：**卡片多了“阅读状态：未阅读”和一个按钮。按钮能点，但状态不变，**这时是正常的**，我们还没告诉它点击后做什么。

- `<span>` 把要变的那三个字单独包起来，稍后只改它，不动“阅读状态：”这几个字。
- `type="button"` 表示普通按钮。
- `aria-live="polite"` 是给辅助阅读工具的提示，让变化的文字更容易被感知；今天保留即可，不作为考点。

**没看到，先检查：**新两行是否在 `<article>` 内；是否保存、刷新。先不调整按钮颜色和位置。

## 第 3 步：给要操作的两个元素起名字（约 10 分钟）

**打开哪里：**刚才新增的状态和按钮两行。

**只做这个动作：**用下面两行替换刚才那两行，只增加 `id`，不是再新增一套状态和按钮。

```html
<p>阅读状态：<span id="note-status" aria-live="polite">未阅读</span></p>
<button id="read-button" type="button">标记已读</button>
```

- `id="note-status"`：给状态元素一个名字。
- `id="read-button"`：给按钮另一个名字。
- 同一页面里的 `id` 要唯一。拼写和大小写都要一致，否则后面的程序找不到。
- 页面上不会显示这两个名字，它们是给程序找元素用的。

**做对时看到：**保存、刷新后，页面外观和第 2 步一样，仍只有一份状态和一个按钮。

**没对上，先检查：**是否把两行重复加了；`id` 是否放在标签内；引号是否使用英文半角引号。

小检查：不用背英文，只要你能在代码里指出“这一个名字对应状态，另一个对应按钮”。然后休息一下。

## 第 4 步：让 JavaScript 找到状态和按钮（约 20 分钟）

**打开哪里：**`index.html` 的末尾。

### 4.1 新增放 JavaScript 的位置（约 5 分钟）

在 `</article>` 后面、`</body>` 前面，新增这一对标签：

```html
<script>
  // 今天的交互代码写在这里
</script>
```

`<script>` 里放 JavaScript。这里让浏览器先读到卡片，再执行脚本，避免程序运行时卡片还没出现。

**做对时看到：**卡片后面有一个完整的 `<script>...</script>`，页面外观没有变化。

**不确定时：**对照第 1 步骨架末尾，确认顺序是 `</article>`、`<script>...</script>`、`</body>`、`</html>`。不要把脚本写进 `<style>` 或某个 `<p>` 里面。

### 4.2 找两个元素并打印出来（约 15 分钟）

把脚本里的那行提示注释替换成下面四行。只输入到 `<script>` 与 `</script>` 之间，不再复制一对脚本标签。

```js
const statusText = document.getElementById('note-status');
const readButton = document.getElementById('read-button');
console.log(statusText);
console.log(readButton);
```

现在只理解这几件事：

| 写法 | 今天把它理解成什么 |
|---|---|
| `document` | 当前网页 |
| `getElementById('note-status')` | 按 `id` 找到那个状态元素 |
| `const statusText = ...` | 给找到的元素取个变量名，后面通过这个名字使用它 |
| `console.log(...)` | 把结果显示到浏览器控制台，方便检查 |

`statusText` 与 `'note-status'` 不必同名：前者是 JavaScript 变量名，后者必须与 HTML 的 `id` 完全一致。英文名字先照用，今天不必另外发明一套。

**检查动作：**
1. 保存文件，切到浏览器刷新。
2. 在浏览器按 `Ctrl+Shift+J` 打开控制台。也可以按 `F12`，选择“Console / 控制台”。笔记本上 F12 可能需要配合 Fn。
3. 再刷新一次，让刚才的脚本重新执行。
4. 看输出的两项：应该分别是包含 `note-status` 的 `<span>` 和包含 `read-button` 的 `<button>`，显示格式可能略有不同。

**做对时看到：**两项都能对应到元素，没有与这段脚本相关的红色报错，状态仍是“未阅读”。

**不对时：**
- 输出 `null`：意思是“没找到”。先对照那一个 `id` 是否写对，再确认脚本在卡片后面。
- 出现红字：先看第一条报错和指向的行。优先对照引号、括号、大小写。
- 什么都没有：确认 Console 标签已选中、没有输入过滤词、日志级别包含 Info，再保存并刷新。
- 不要把陌生网站给的命令粘进控制台；这里用它观察自己文件的输出即可。

若此时还找不到元素，先解决这一步，不继续往下加函数。

## 第 5 步：写一个“把状态改成已阅读”的动作（约 15 分钟）

**打开哪里：**同一个 `<script>`，刚才两个 `console.log` 的下面、`</script>` 的前面。

**只做这个动作：**保留前面的四行，新增下面这一个函数。

```js
function markRead() {
  statusText.textContent = '已阅读';
}
```

一行一行理解：
- `function markRead()`：给这个动作起名叫 `markRead`。
- `{` 和 `}`：包住这个动作需要做的事情。
- `statusText`：第 4 步找到的状态元素。
- `.textContent`：这个元素里的文字内容。
- `= '已阅读'`：把文字设为“已阅读”。这里的 `=` 是赋值，不是在问两边是否相等。

今天的函数没有输入参数，圆括号先空着。`const` 不允许把 `statusText` 这个变量重新指向别的值，但可以修改它所指向元素的文字，所以这段代码可以工作。

**做对时看到：**保存、刷新后仍是“未阅读”，点按钮也还没反应。定义函数只是准备好了动作，尚未让按钮调用它。

**不对时：**控制台出现红字，先看 `{}`、括号、英文引号是否配对，`statusText` 是否与第 4 步一致。今天不用背“函数”的标准定义，只要知道它是一段可以被调用的动作。

## 第 6 步：把按钮和动作接起来（约 10 分钟）

**打开哪里：**同一个 `<script>`，刚才函数结束的 `}` 后面、`</script>` 前面。

**只做这个动作：**在函数外新增一行：

```js
readButton.addEventListener('click', markRead);
```

这句可以读成：**让 `readButton` 监听点击；以后每次点击，就执行 `markRead`。**

- `'click'` 表示点击事件。
- 这里写 `markRead`，不是 `markRead()`。前者把动作交给按钮，后者是现在就执行动作。
- 注册监听这行放在函数外，不放进函数的大括号中。

**检查动作：**
1. 保存、刷新，先别点：应该显示“未阅读”。
2. 点击“标记已读”：应该变成“已阅读”。
3. 再点一次：仍然是“已阅读”，不是每次点都要出现不同的字。
4. 看控制台：不应新增与这段交互相关的红色报错。

**不对时：**
- 还没点就变了：检查是否误写成 `markRead()`，或者在其他地方提前调用了它。
- 点了没反应：检查这一行有没有写、是否在函数外、`readButton` 和 `markRead` 的拼写是否一致。
- 一点击就报错：优先检查函数里的 `statusText.textContent`。

先别继续加功能。你刚完成了“点击 → 执行动作 → 改页面文字”，可以休息一下。

## 第 7 步：小改一次，确认不是只照着敲（约 15 分钟）

**打开哪里：**刚才的 `markRead` 函数。

**只做这些动作：**
1. 先预测：如果把函数里的“已阅读”改成“今天读完了”，点击后会怎样？
2. 只修改函数里的那段文字，不改 HTML 里的初始“未阅读”。
3. 保存、刷新，先看初始状态，再点击按钮。
4. 对照自己的预测，最后把函数里的文案改回“已阅读”，保存、刷新。

**做对时看到：**修改文案后，刷新仍显示“未阅读”；点击才显示“今天读完了”。恢复代码后又回到原来的交互。

**不对时：**一刷新就显示新文案，看看是否改成了 HTML 里的初始文字；完全没变则检查是否保存、刷新，以及修改的是不是当前文件。

### 一个必须知道的现象

点击变成“已阅读”后，再刷新网页，会重新显示“未阅读”。**这是今天的预期结果。**

我们只修改了浏览器当前页面里的文字，没有把阅读状态写回文件或数据库。刷新会重新读取 HTML 中的“未阅读”。今天不做保存状态的功能。

浏览器把 HTML 中的文字、按钮等变成可以被程序操作的页面元素，这里涉及 DOM。你现在是通过 JavaScript 直接改元素；到 Day04 才会体验 Vue 如何根据数据变化更新页面。

### 自己走一遍这张检查表

| 操作 | 预期结果 |
|---|---|
| 打开或刷新文件，暂不点击 | 未阅读 |
| 点击一次“标记已读” | 已阅读 |
| 连续再点击两次 | 仍是已阅读 |
| 刷新 | 回到未阅读 |
| 临时改函数文案，保存刷新后点击 | 显示新文案 |
| 恢复函数文案，保存刷新后点击 | 再次显示已阅读 |

## 随时可查：常见现象与先查哪里

| 现象 | 先检查 |
|---|---|
| 改了文件，但浏览器还是旧内容 | 保存了吗？刷新了吗？打开的是 `day01/index.html` 吗？ |
| 页面显示 HTML 源代码 | 文件是否误存成 `.txt`？打开方式是否是浏览器？ |
| 控制台打印 `null` | HTML 的 `id` 和 JS 引号里的名字是否完全一致？脚本是否在卡片后面？ |
| `... is not defined` | 提示中的变量或函数是否拼错、尚未声明？例如 `markRead` 与 `markread` 不同 |
| `Cannot set properties of null` | 状态元素没找到，先检查对应 `id`，不要只改赋值那行 |
| `Cannot read properties of null`，提到 `addEventListener` | 按钮没找到，检查按钮的 `id` 和脚本位置 |
| `SyntaxError` 或红色波浪线 | 英文引号、圆括号、大括号有没有缺失或多写？一次只改一个问题 |
| 还没点击就变“已阅读” | 监听那行是否误写了 `markRead()`？是否有单独调用函数的语句？ |
| 函数写了，点击还是没反应 | 监听那行是否漏写、放进函数内部，或按钮变量用错？ |
| 写第二个按钮后出现 `already been declared` | 是否重复用了同一个 `const` 变量名？给新按钮使用新的变量名，不要重复声明原状态元素 |
| 刷新后状态回到未阅读 | 今天没有持久化，这是正常的 |

查看报错时优先读第一条和对应行，不需要先看懂所有英文。报错截图要包含完整第一条，代码则尽量发文本，便于检查。
